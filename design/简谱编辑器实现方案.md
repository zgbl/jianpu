**简谱与吉他伴奏编辑器：实现方案**

**1. 结论**

采用“结构化乐谱数据 + 自动排版引擎 + SVG 乐谱画布 + 可视化编辑”的架构。数字、八度点、减时线、附点、连线分别绘制，不使用普通文本的上标/下标来拼乐谱。用户编辑的是音高、时值、歌词、和弦等音乐属性；引擎负责它们的位置。

项目目前为空目录，本方案是新项目的设计起点。交付路径为项目下的 `design/`，将用户提到的“下载/design folder”理解为保存可取用的方案文件。

**2. 从示例确定产品范围**

参考图不是只有旋律简谱，而是同步展示：上层和弦名称与指法图，中层吉他六线谱及拨弦节奏，下层旋律简谱及歌词。还包含调号、拍号、变调夹、反复记号、圆滑线、多段歌词与文字说明。

目标支持两种视图：

- 简谱模式：和弦名称/指法图 + 旋律简谱 + 歌词。
- 吉他编配模式：再加入六线谱、拨弦节奏、品位数字。

旋律与伴奏可以有不同节奏，但必须共享小节边界和时间位置。图片只用来分析版式；第一批验证曲谱使用原创短句，不依赖识别这张图片中的全部音符。

**3. 解决最关键的符号排版问题**

每个音符是一个图形组，有稳定的 eventId、音乐时间、字形边界与可点击区域。

| 元素 | 音乐数据 | 绘制方式 |
| --- | --- | --- |
| 数字 1–7 | 音级与升降记号 | SVG text；统一数字字体、字号与基线 |
| 高音点 | octaveOffset > 0 | 数字上方独立 circle，逐层向上 |
| 低音点 | octaveOffset < 0 | 数字下方独立 circle，避开减时线 |
| 八分/十六分音符 | baseDuration | 数字下方一条/两条 line；跨音符连接由节奏组控制 |
| 附点 | dots | 数字右侧 circle；与八度点使用不同锚点 |
| 延长线 | 较长的记谱时值 | 独立横线与时间槽，不写成任意长度字符串 |
| 休止符 | rest | 0，应用对应时值记法 |
| 延音线/圆滑线 | 两端 eventId | 贝塞尔 path；跨行时分段绘制 |
| 连音组 | tuplet 比例与成员 | 数字及括号；实际时长使用有理数 |
| 歌词 | eventId、verse、音节 | 独立文本层；多段歌词分别占一行 |

纵向占位顺序默认是：连线 → 高音点 → 数字 → 减时线 → 低音点 → 歌词。低音点放在减时线以下，具体距离由样式参数和碰撞检测计算。多个八度点、双减时线、连线相遇时扩大行高，不能覆盖或裁切。

节奏线按拍子分组，例如 4/4 通常按四分拍分组，6/8 通常按附点四分拍分组；提供人工分组覆盖。长音显示、休止符长时值及跨小节拆分应形成明确的记谱规则集，避免把“播放时长”直接等同于“要画几条横线”。

**4. 数据模型：音乐内容和页面位置分开存**

建议保存带版本号的 JSON；布局结果为可重新计算的缓存，不是原始数据。

```ts
type Fraction = { n: number; d: number }; // 约分后的精确有理数
// 时间单位：四分音符 = 1；4/4 小节长度 = 4；6/8 = 3。
type MelodyEvent = {
  id: string;
  start: Fraction;                 // 小节内位置
  duration: Fraction;              // 实际时长
  pitch: null | { degree: 1|2|3|4|5|6|7;
                  octaveOffset: number; alter: number };
  notation: { base: 1|2|4|8|16|32; dots: number; tupletId?: string };
};
type ChordEvent = {
  id: string; start: Fraction; symbol: string; shapeId?: string;
};
type TabEvent = {
  id: string; start: Fraction; duration: Fraction;
  notes: Array<{ string: 1|2|3|4|5|6;
                 fret?: number; mark?: 'pattern'|'muted' }>;
};
```

补充对象：Score（标题、作者、速度、调性、拍号）、Measure（稳定 ID、拍号变化、反复边界）、Voice（独立声部）、Lyrics（音符 ID、段落、音节、连字符与拖腔）、Spanner（tie/slur）、ChordShape（六弦品位、手指、横按、起始品位）、LayoutPreferences（纸张、行距、建议换行）。

关键约束：

- 休止用 pitch=null；尚未填写的空位是另一种编辑状态，不能静默变为休止。
- base/dots/tuplet 推导的时长必须与 duration 一致；修改时一次性更新。
- 每声部检查小节容量；不足显示提示，超出阻止或按明确命令拆分。
- tie 连接同音高并延续发声；slur 表示乐句，二者不能合并。
- 图片中的叉号可能表示编配拨弦位置，不能全部当成闷音。伴奏模板标记与实际闷音分别存储；需模板定义或用户指定后才能生成播放声音。
- 和弦符号与指法图分离。同一个 C 可以有多种指法，保留自定义。
- 调性含主音、调式和参照八度；变调夹与谱面调、实际发声调分开，避免重复升调。
- 转调区分“保持音级、改变发声调”和“保持绝对音高、重新拼写”；界面给出结果预览。

**5. 排版引擎：先对齐时间，再处理碰撞**

1. 校验数据并计算每声部的精确时间。
2. 合并旋律、伴奏、和弦的所有时间起点为小节时间槽。
3. 测量数字、歌词、指法图、升降号的最小占位。
4. 对相邻槽建立最小间距约束；和弦图等跨槽内容也加入约束。
5. 以节奏比例分配剩余宽度；不是简单按音符数量等分。
6. 根据每小节最小宽度装入乐谱行。先实现贪心换行，后续加入全段优化。
7. 计算各层高度、减时线组、连线、反复记号，解决纵向碰撞。
8. 输出 SVG 图形和 eventId → boundingBox 映射，供选择、光标及播放高亮使用。

同一时刻的旋律与六线谱落在同一个 x 坐标；同一行所有层的小节线保持一致。和弦图比音符宽时应扩大局部间距或小节宽度，而非挤压歌词。特别宽的小节优先独占一行；仍放不下时提示调整纸张或字号，不静默裁剪。

中文字体加载完成后才能做最终测量，导出也等待字体就绪。谱面字号使用逻辑单位，屏幕缩放只做视图变换。

**6. 编辑体验**

页面中央为所见即所得谱面，上方工具栏设置时值、附点、八度、升降号、连线、休止；右侧显示选中音符、小节或和弦的属性。歌词通过临时 HTML 输入框编辑，提交后回到 SVG 文本层，支持中文输入法组合输入。

基本流程：新建 → 设置调号/拍号 → 输入旋律 → 对齐歌词 → 添加和弦 → 可选生成并调整吉他伴奏 → 校验 → 保存/打印。

- 按 1–7 输入音符，0 输入休止；保留最近选择的时值。
- 方向键移动光标；按钮调整八度与时值，快捷键方案后续验证。
- 明确区分插入和替换。插入超出小节时提示用户选择跨小节重排；替换改变时值时也检查容量。
- 点击选音符、Shift 扩选、框选片段；支持复制、粘贴、删除、撤销和重做。
- 歌词以音符 ID 对齐，可逐音节输入；一字多音使用拖腔标记，不靠空格定位。
- 添加 Em/C/G 等和弦后选择指法图；指法编辑器可切换空弦、禁弹、品位与横按。
- 六线谱先选择弦与时间位置，再输入品位或编配标记。伴奏模板填入独立声部，不覆盖旋律。
- 自动排版是默认；提供换行建议、歌词偏移及指法图偏移等少量语义化覆盖，重排后依然有效。

SVG 负责显示，编辑命令通过统一事务修改乐谱数据。输入焦点在歌词框时，数字快捷键不能插入音符。提供可聚焦音符列表及音高/时值的文字描述，键盘操作不能只依赖鼠标点击图形。

**7. 技术方案与目录**

建议 Web 优先，使用 TypeScript + React + SVG，构建工具可选 Vite。React 管理工具栏与交互层；独立纯函数引擎负责音乐校验及布局。具体依赖版本在实现时确认。

```text
src/
  music/       数据模型、时长、调性、校验、转调
  layout/      字形测量、时间槽、换行、碰撞处理
  render/      SVG 简谱、六线谱、指法图、打印
  editor/      命令事务、光标、选择、撤销、输入法
  playback/    时间轴与音频调度（第二阶段）
  io/          JSON 保存、迁移、导出
  ui/          工具栏、属性面板、歌词与和弦编辑
fixtures/      原创边界测试乐谱
design/        设计与验收资料
```

选择 SVG 是因为文本、直线、圆点和曲线都可以独立定位并保持矢量输出；依据 [SVG 文本规范](https://www.w3.org/TR/SVG/text.html) 和 [SVG 路径规范](https://www.w3.org/TR/SVG/paths.html)。这是架构建议，不代表现成库已经覆盖全部简谱规则。

首版直接实现简谱绘制，不把通用五线谱库是否支持数字谱作为阻塞前提。以后需要互通时增加 MusicXML 适配层，其官方示例包含六线谱弦号、品位和调弦数据：[MusicXML 4.0 六线谱示例](https://www.w3.org/2021/06/musicxml40/musicxml-reference/examples/tutorial-tablature/)。自定义简谱样式及未知拨弦标记不保证能无损往返；JSON 始终是原生格式。

**8. 分阶段实现与验收**

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| P0 排版验证 | 原创 8 小节静态 SVG，覆盖数字、点、线、歌词、指法图、六线谱 | 放大、缩小、打印后不重叠；三层时间与小节线对齐 |
| P1 可编辑简谱 | 输入、选择、时值/八度修改、歌词、撤销、JSON 保存加载 | 编辑后重排正确；刷新/加载后内容一致；错误小节可定位 |
| P2 吉他编配 | 指法库、自定义指法、六线谱、分解和弦模板 | 改和弦不改旋律；独立节奏准确对齐；跨小节复制可靠 |
| P3 发布能力 | SVG/PDF、试听、转调、反复播放、自动保存 | 纸面无截断；试听与视觉时值一致；反复与变调夹发声正确 |

PDF 优先采用与屏幕相同布局结果生成打印 SVG 页面，再通过浏览器打印；多页分页由引擎按整行完成，不能任由浏览器截断谱行。字体、页面尺寸与导出稳定性需要实际验证。

每阶段估时取决于是否支持多声部、复杂连音和专业印刷；先用 P0 验证视觉效果再估完整开发量，避免承诺未经验证的工期。

**9. 必须验证的难例**

- 双低音点 + 十六分减时线 + 附点 + 歌词同时出现。
- 一个小节有长中文歌词、两个宽指法图，另一声部节奏更密。
- 圆滑线与延音线跨行，跨小节长音正确拆分且歌词不重复。
- 4/4、6/8、弱起、三连音、反复开始/结束；弱起以显式小节容量处理。
- 多段歌词、一字多音、英文连字符、中文输入法。
- 编辑时值导致溢出、删除连线端点、粘贴跨多个小节、连续撤销重做。
- 高低音、升降号、变调夹参与播放映射；没有品位定义的编配标记不生成虚构音高。
- A4 多页、不同缩放、字体未加载、保存后重开；布局和内容均可复现。

测试分为音乐模型单元测试、少量布局快照、真实浏览器编辑测试和导出视觉检查。验收首先看“符号是否准确、层间是否对齐”，再做视觉风格优化。

**10. 推荐立即开始的工作**

先做 P0：一个 8 小节原创谱面的 SVG 渲染原型，同时覆盖低音点、双减时线、连线、两段歌词、Em/C/G 指法图和吉他六线谱。随后让其中一个音符支持点击后修改八度与时值，并即时重排。这个原型能直接证明最困难的显示和编辑问题已被解决，再扩展完整编辑器。
