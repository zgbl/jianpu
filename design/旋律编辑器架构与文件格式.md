**旋律简谱编辑器 v0.1：实际实现说明**

**范围与验收目标**

本版只处理旋律，包含数字音符、0 休止、上下八度点（各两组）、八分/十六分减时线、附点、长音延长线、小节线、延音线、圆滑线、反复起止、单个前倚音。每个符号来自数据属性，支持选择与修改。吉他、歌词不进入本版。

谱例 A/B 根据用户截图可见音符人工录入，每小节四拍。谱例 C 根据可见减时线录入，五个小节各两拍，推定为 2/4；截图未显示拍号，该推定需要与完整原谱核对。截图未给调号，默认 1=C；这是可编辑假设。没有图片识谱功能。

**技术栈**

| 层 | 本版实际选择 | 作用 |
| --- | --- | --- |
| 界面 | HTML、CSS、JavaScript ES Modules | 工具栏、属性编辑、事件处理 |
| 乐谱画布 | SVG text / circle / line / path | 字符、点、线和曲线独立定位 |
| 原生文件 | UTF-8 JSON，扩展名 .jianpu，版本 2 | 保留全部音乐属性和连线关系 |
| 自动保存 | localStorage | 同一浏览器的本地草稿 |
| 启动 | Node.js 20+，内置 HTTP 服务 | localhost 静态资源服务 |
| 验证 | node:test；Playwright 浏览器检查 | 模型、排版边界与编辑操作 |

运行项目不需要 npm install，也没有 CDN 依赖。首版使用原生 JavaScript 是为了让排版与音乐规则先独立运行，避免引入与问题无关的框架成本。后续若加入 React 或 TypeScript，保持 model/layout/render 的边界，界面框架不拥有音乐语义。

**架构与职责**

```text
界面操作
  ↓
app.js：编辑事务 → validate → 撤销记录 → 保存草稿
  ↓
model.js：音符、小节、时长、连线与格式约束
  ↓
layout.js：占位、时间位置、减时线分组、小节换行
  ↓
render.js：生成 SVG，event ID 对应可点击音符组
```

- `src/model.js`：定义文件对象，整数时值、小节容量、导入验证与 v1 迁移、插入/修改/删除、连线约束及示例。
- `src/layout.js`：纯计算层；输出音符坐标和行号、每小节尺寸、减时线组。没有 DOM 操作。
- `src/render.js`：布局结果转 SVG；不修改乐谱。导出移除选择色和编辑信息。
- `src/app.js`：光标、Shift 范围选择、属性编辑、原子提交、撤销/重做、文件读写。
- `server.mjs`：本地静态服务，不保存用户数据到服务器。

失败的编辑事务会恢复乐谱和选择状态。例如把满小节中的八分改成全音符，会提示超出拍号容量并保留原谱。修改被延音线连接的音高，会提示同音高约束；用户先移除延音线，再改音高。

**原生文件格式**

```json
{
  "format": "jianpu-melody",
  "version": 2,
  "title": "我的旋律",
  "key": "C",
  "meter": [4, 4],
  "measures": [
    {
      "id": "measure-1",
      "repeatStart": false,
      "repeatEnd": false,
      "notes": [
        {
          "id": "note-1",
          "degree": 6,
          "base": 8,
          "octave": -1,
          "dots": 1,
          "beamBreak": false,
          "grace": { "degree": 5, "octave": 0, "base": 16 }
        },
        { "id": "note-2", "degree": 6, "base": 16, "octave": -1, "dots": 0 }
      ]
    }
  ],
  "spans": [
    { "id": "span-1", "type": "tie", "from": "note-1", "to": "note-2" }
  ]
}
```

`degree=0` 为休止；1–7 为音级。`octave=-1` 一个低音点、`+1` 一个高音点。`base=1/2/4/8/16` 是全/二分/四分/八分/十六分。`dots=1` 时值乘 1.5。`grace` 是不占独立小节拍数的前倚音，绘制小数字、八度点、减时线和小弧线；本版每个主音只支持一个倚音。

本版固定时间单位：全音符 64 ticks，四分 16，八分 8，十六分 4，附点十六分 6。音符起点由前面音符累计推导，不在文件里重复存储。4/4 小节容量 64，2/4 小节容量 32。三连音以后必须换为精确有理数或可整除的统一时间基准；不能直接把浮点数混进当前文件。

连线独立存储，用稳定 ID 指向端点。`tie` 限定相邻同音高音符；`slur` 可以连接不同音高。删除音符时同时删除它关联的连线。反复只保存边界；本版没有播放展开。

不保存 x/y、SVG 或上标 HTML。改变音符时值、添加倚音、换行后重新生成全部布局，不会留下旧坐标。

导入会检查版本、拍号、音高、时值、八度、ID 唯一性、连线端点和小节超拍。空小节和不足拍的小节作为草稿允许保存，谱面明确标注未填满。文件大小上限 2MB、小节上限 200。JSON 是可编辑文件；SVG 是呈现文件，不能用于无损导回。

**符号排版如何实现**

1. 每个音符获得数字基线。高音点位于基线上方，低音点位于减时线下方；附点固定在数字右侧。
2. 音符用时值和符号需求计算最小宽度。全音符留下三个延长线位置；附点与倚音增加额外占位。
3. 同一四分拍中连续短音组成减时线组：主线跨组连接，第二层只连接相邻十六分音符。`beamBreak=true` 可人工断组。混合时值需要分别处理每一层，不能画一根统一下划线。
4. 小节保持完整，超过行宽就换行。当前使用固定逻辑行宽，屏幕缩放不改变音乐数据。
5. 连线使用三次贝塞尔曲线。根据端点的行号拆成行尾、必要的中间行、下一行行首。重叠的连线分配不同高度。
6. 倚音预留左侧空间，使用小字号与独立减时线及小连线，不增加主时间轴上的音符。

这是最小排版引擎，还不是成熟出版级引擎：音符间距是有最小宽度的近似时值比例；没有全曲最优断行，很多层叠连线也尚未做全面碰撞求解。需要用更复杂的真实乐谱继续扩充边界验证。

**实际编辑步骤**

1. 载入 A/B/C 谱例，或添加空小节。
2. 点击音符，修改音高、时值、八度、附点，按“修改选中音符”。修改后立即重排。
3. 插入音符：选择时值与八度，再按数字按钮/数字键。选中音符后插在其后；小节空白处点击后在末尾插入。
4. 连线：点击起音，Shift 点击止音，再选择延音线或圆滑线。延音线必须相邻同音高。
5. 倚音：选择主音，设置倚音音高/八度/时值，再添加。主音与倚音分别编辑。
6. 在当前小节切换反复起止，使用断组属性调整减时线。
7. 保存 `.jianpu` 文件；重新打开保留音乐结构；导出 SVG 保留所有符号。

**当前限制**

支持 4/4 与 2/4，单声部，无升降号、三连音、后倚音、多个连续倚音、跨小节自动拆分、播放、PDF 专用分页和图片识谱。不自动填休止，不自动把超出拍数的音符移到下一小节。调号仅为谱面元数据，尚未包含转调或声音映射。

下一步优先与完整原谱核对第三张谱例的拍号，并扩展按拍分组的人工连接覆盖、碰撞求解及端点拖动；再做更丰富拍号和精确有理数时间模型。不能以“能显示数字”作为完成标准。
