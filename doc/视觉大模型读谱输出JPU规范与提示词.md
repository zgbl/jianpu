# 视觉大模型读简谱：输出 JPU 的规范与提示词

本文件可以和**一首歌的全部谱图**一起发给支持多图输入的视觉大模型。目标是让模型按图片中的简谱旋律，直接返回本项目可读取的 `.jpu` 内容。先逐图、逐行、逐小节读谱，再生成 JSON；不要让拍号或常见旋律替图片“纠错”。吉他六线谱、指法图和扫弦节奏不进入旋律音符；读取其上方的和弦字母即可。

`.jpu` 是 UTF-8 编码的 JSON 文件，顶层 `format` 必须为 `jianpu-melody`，`version` 必须为 `2`。下文所称“输出 JPU”指**只输出一个完整 JSON 对象**，不加 Markdown 代码围栏、开场白或解释。用户可以把它保存为 `歌名.jpu`；也可以在“大模型读谱”工作台直接贴多张图，页面会把本规范与图片发送给 Gemini 并渲染结果。本机“图片识谱”页面仍独立使用 Apple Vision OCR。

## 先读什么

1. 按图片顺序、从上到下读每一条真正的**简谱旋律行**。同一页可能还包含吉他六线谱、歌词和弦、前奏或尾奏；不要把六线谱品位数字当作简谱数字。跨页重复拍到的小节只能保留一次。如果分页衔接不确定，在 `visionReview.issues` 写明。
2. 以**印刷的小节线**划分小节，按实际顺序给小节编号。普通 `|` 是边界；`||:` 或 `|:` 是后面小节的 `repeatStart`；`:||` 或 `:|` 是前面小节的 `repeatEnd`。终止线可标 `final: true`。不可凭“每四个数字”推断小节线。
3. 逐一读 `0–7`、升降号、数字上下的八度点、数字右边的附点、数字下方的减时线、数字之后的延长横线、倚音、连音弧线、带数字 3 的三连音括号及歌词。区分数字右侧附点 `3.` 与音符下方的低八度点；区分延长横线 `—` 与下方减时线。
4. 标题、`1=...`、拍号、Capo、和弦名称照图读取。**简谱的 `1` 和吉他指型调不是一回事**：例如谱面写“C 指型、Capo 2”，实际发声音高的 `1` 是 D；简谱数字仍然是 `1、2、3...`。谱上印的 C 指型和弦要以实际和弦 D 存入 JPU，同时设置 `guitarNotation`，使界面仍能显示 C 指型。若图片没有足够信息确定实际 Do，不要依据歌曲名或听过的版本猜调，在 `visionReview.issues` 标明。
5. 和弦按**印刷位置**对应小节。小节中间有换和弦时，当前 JPU 的 `chords` 只记录所属小节、无法保留精确拍位；把拍位或“半小节换和弦”写入 `visionReview.issues`，不要静默挪到下一小节。

## JPU 字段

| 位置 | 必填字段与含义 |
| --- | --- |
| 顶层 | `format: "jianpu-melody"`、`version: 2`、`title`、`key`、`meter`、`measures`、`spans: []`、`lyrics: []`。`key` 是**实际发声**的 Do，允许 C、C#、Db 等十二平均律音名；`meter` 支持 `[2,4]`、`[3,4]`、`[4,4]`、`[6,8]`。 |
| 小节 | `id`（全谱唯一字符串）、`notes`（顺序数组）、`repeatStart`、`repeatEnd`（两个布尔值）。需要时可加 `final: true`。每条印刷小节线都要体现在两个相邻小节的分界中。 |
| 音符 | `id`（全谱唯一字符串）、`degree`（0=休止，1–7=唱名；视觉模型常把高八度主音写成 8，页面导入时会兼容解释为 `degree:1` 并将 `octave` 加 1）、`base`（1、2、4、8、16）、`octave`（-2、-1、0、1、2）、`dots`（0 或 1）。`accidental` 可选，-1=降、0=无、1=升；休止符的 `octave` 必须为 0，不得有升降号。 |
| 连线 | `spans` 元素为 `{ "id": "s001", "type": "tie" 或 "slur", "from": "音符ID", "to": "音符ID" }`。延音线 `tie` 只连**相邻、同音高、同八度、同升降号**的两个音符；圆滑线用 `slur`，可以跨其他音符或小节。 |
| 歌词 | `lyrics` 元素为 `{ "noteId": "音符ID", "verse": 1, "text": "字" }`。同一音符、同一段只能有一项。多段歌词用 `verse: 1–4`；字在图上对应哪个数字，就引用哪个数字的 ID。休止符、延音线的后续音通常不挂新字。只有图片确实显示数个字唱在同一个音符上，才把它们放在同一个 `text`。 |
| 和弦 | 可选 `chords` 元素为 `{ "measureId": "小节ID", "label": "G", "source": "image" }`。`label` 使用实际发声和弦，如 `C`、`G7`、`Am`、`Fmaj7`、`G/B`，包括斜杠低音。不要根据流行和弦进行自行配和弦。 |
| 吉他 | 有明确指型与 Capo/调弦移调时，可选 `guitarNotation: { "version": 1, "mode": "fingering", "shapeKey": "C" 或 "G", "capo": -12–12 }`。负值表示标准调弦整体降调；`key` 和存储的和弦仍是实际发声调/和弦；该字段只控制指型显示。无可靠信息就省略。 |
| 复核 | 可选 `visionReview: { "sourcePages": 图片张数, "issues": [...] }`。此字段是本提示词要求的审校记录，项目当前不会拿它推断音符；每项建议写 `page`、`measure`、`kind`、`description`。不确定的内容不能伪装成确定读数。 |

`id` 不必是真 UUID，`m001`、`n001_01`、`s001` 这样的稳定字符串即可，但**所有小节、音符和连线的 ID 必须互不重复**。歌词与和弦引用的 ID 必须确实存在。`pitchMidi`、`sourceTime` 是录音识别字段，纯图片识谱**不要填写**；不要编造 BPM 或音频时间。

## 节奏与符号如何编码

以四分音符为 1 拍：无减时线 `base:4` 为 1 拍；一条减时线 `base:8` 为 0.5 拍；两条减时线 `base:16` 为 0.25 拍；二分音符 `base:2` 为 2 拍；全音符 `base:1` 为 4 拍。右侧附点设 `dots:1`，时值乘 1.5。高/低八度点只改 `octave`，**不改时值**。模型若把高八度 `1` 输出为 `degree:8`，导入器会视为常见别名，转换成 `degree:1`、`octave + 1`，并生成橙色复核项；请优先直接按规范输出 `degree:1` 与八度点。转换后的八度超出支持范围时，音符会作为待核占位显示，不会强行认定。倚音放在主音的 `grace` 字段，例如 `{ "degree": 5, "octave": 1, "base": 16 }`；它不占小节拍数。

图片上 `1 —` 通常是一个四分 `1` 再延长一拍：若确实分成“数字 + 延长横线”两个印刷位置，输出两个相邻的 `1`、各 `base:4`，并用 `tie` 连接；`1 — —` 则三个相邻音符、两条 `tie`。**不要把横线读成休止符**。跨小节延长线也要保留两侧音符及连线。若原图本身就是清楚的二分或全音符符号，直接用 `base:2` 或 `base:1`。休止 `0` 按它实际印刷的减时线/附点编码；较长休止可用二分或全休止，绝不将休止与有音高的音符相连。

每个普通小节的时值总和应等于拍号，例如 4/4 为 4 拍。**先核图，再算拍**：若不足或超出，逐个检查漏音、减时线数、附点、延长横线和小节边界。不得为了凑四拍而添加看不见的音符或休止符。真实弱起小节、残缺截图或原谱印刷错误可不满拍，但必须在 `visionReview.issues` 说明原因和位置。跨页衔接时不能把同一小节重复算两次。

## 一个最小、有效的 JPU 示例

以下是**字段示例，不是任何上传图片的读谱结果**。第 1 小节为 `3 3̲ 4̲ 6 5`（4/4）；第 2 小节为 `1 — 0 2`，其开头有反复开始记号。示例两个小节各 4 拍。

```json

  "version": 2,
  "title": "示例旋律",
  "key": "C",
  "meter": [4, 4],
  "measures": [
    {
      "id": "m001", "repeatStart": false, "repeatEnd": false,
      "notes": [
        {"id":"n001_01","degree":3,"base":4,"octave":0,"dots":0},
        {"id":"n001_02","degree":3,"base":8,"octave":0,"dots":0},
        {"id":"n001_03","degree":4,"base":8,"octave":0,"dots":0},
        {"id":"n001_04","degree":6,"base":4,"octave":0,"dots":0},
        {"id":"n001_05","degree":5,"base":4,"octave":0,"dots":0}
      ]
    },
    {
      "id": "m002", "repeatStart": true, "repeatEnd": false,
      "notes": [
        {"id":"n002_01","degree":1,"base":4,"octave":0,"dots":0},
        {"id":"n002_02","degree":1,"base":4,"octave":0,"dots":0},
        {"id":"n002_03","degree":0,"base":4,"octave":0,"dots":0},

  "lyrics": [{"noteId":"n001_01","verse":1,"text":"我"}],

}
```

## 发给视觉大模型的提示词

把下面整段连同**按顺序排列的全部图片**发送给模型；上面的规范和示例也一并发送。

> 请充当人工读谱员，把附件图片里的**简谱旋律**逐页、逐行、逐小节转写为上文规定的 `jianpu-melody` version 2 JPU JSON。请先在内部建立“图片页码 → 简谱行 → 印刷小节 → 音符/歌词/和弦”对应表，再生成最终 JSON。严格依据可见符号，不能从歌曲名、网上记忆、和弦进行、吉他六线谱数字或拍号推测缺失旋律。
>
> 逐音确认数字、休止、升降号、高低八度点、右侧附点、下方一条/两条减时线、延长横线及连音弧线；按真实小节线分段，包括 `||:`、`:||`、跨行边界。歌词逐字绑定到图上对应的音符；不要漏字，也不要为了塞进某一拍把相邻字合并。只抄图片上标出的和弦，并放在其对应的小节。
>
> 若图片标 C/G 指型和 Capo，请区分指型调与实际 Do：简谱数字不变，`key` 与 `chords.label` 为实际发声调/和弦，`guitarNotation` 记指型与品数；不要移调两次。若调号或 Capo 看不清，在 `visionReview.issues` 明示，不能自作决定。
>
> 输出前逐小节计算拍数，通常应与拍号相等；对不足/超拍的小节回看原图，查漏音、附点、横线、小节边界。若仍不能确定，**不要编造音符凑拍**，在 `visionReview.issues` 给出页码、小节号、可见内容与疑点。若有任何关键音符或边界完全无法辨认，输出 `{ "status": "needs_clearer_image", "issues": [...] }`，不要输出看似完整的假 JPU。
>
> 自检：JSON 能解析；所有 ID 全谱唯一；歌词、和弦、连线引用的 ID 存在；`tie` 连相邻同音；普通小节拍数正确；每个可见音符、歌词字、和弦和反复号都有对应数据；分页处不重复。最终只输出 JSON 对象，不加 Markdown 代码围栏或说明。

## 交付后的核对顺序

### 页面导入的容错与自动修正

本规范描述模型应尽量输出的**标准格式**；页面导入器对可恢复的格式偏差采取宽容策略，让用户先看到草稿，而不是因一个局部字段错误拒绝整首谱。页面修复会在谱面上方列出橙色复核项，不能当作已确认识别。

- `degree:8` 作为高八度 `1` 的常见别名处理，转换为 `degree:1` 并给 `octave` 加 1，显示并提示核对八度点。
- 数字字符串转成数字；缺失的 `octave`、`dots`、小节反复布尔值采用中性默认值；缺失或重复的对象 ID 自动重建。
- 无法解释的音高以休止符占位；无法解释的时值用四分音符占位。原字段保存在待核数据中并显示警告，不能视为识别正确。超出当前支持范围但能明确缩窄的 32 分音符暂按 16 分音符显示并要求核对。
- 错误三连音标记会从整组音符上移除，音符仍显示为普通节奏并提示核对；有效三连音会保留。无效歌词引用、和弦、连线或扩展元数据会隔离到待校信息，不会阻止可用旋律显示，也不会自动猜测歌词位置、和弦名称或音高。
- 无法解析的 JSON、不是 JPU v2 的输入、模型明确返回 `needs_clearer_image`，仍不能安全生成乐谱，会说明原因。

请模型尽量遵循标准字段，不要依赖页面修复。容错导入的目标是“可见、可复核”，不是“自动证明内容正确”。

先检查模型返回的 `visionReview.issues`，再逐小节查看数字、八度点、拍数及小节线，接着查歌词对应、和弦及 Capo、反复记号。`.jpu` 通过本项目的数据校验，只能证明**结构合法**，不能证明视觉识别正确。打开工作台第三个入口“**大模型读谱导入**”，可直接贴图点“识别全部图片”；也可以粘贴外部模型返回的 JSON，点“转换并预览”。确认后可下载 `.jpu`，或点“导入当前工程并编辑”。

## 页面内视觉模型复核协议

在乐谱预览中点击需要复核的小节，可为每小节填写具体疑点，再点击“用所选模型复核标记小节”。页面会再次发送全部原图、当前 JPU 与标记的小节，要求模型仅返回 `jianpu-measure-revision` version 1 JSON。`updates` 每项包含 `measure`（从 1 开始）、该小节的**全部** `notes`、`chords` 数组及可选的 `repeatStart`、`repeatEnd`、`final`、`spans`；每个音符可含 `lyrics: [{"verse":1,"text":"字"}]`。`spans` 用小节内音符的零基 `from`／`to` 索引。`issues` 记录依然无法确定的读数。系统只合并已标记的小节，未标记小节保持原样；不合法的回复不应用。复核前一版可以在页面返回。跨小节连线需要导入后人工核对。

在项目根目录 `.env` 中填入所需密钥即可；文件已被 Git 忽略，服务端每次请求读取，不需反复在页面粘贴。`.env.example` 是不含密钥的模板。可选 `GEMINI_API_KEY`、`OPENAI_API_KEY`、`QWEN_API_KEY`、`DEEPSEEK_API_KEY`；若使用阿里百炼密钥，也可填 `DASHSCOPE_API_KEY`。页面可选 Gemini、OpenAI、Qwen 3.8、DeepSeek，默认模型分别为 `gemini-3.6-flash`、`gpt-5.4`、`qwen3.8-flash`、`deepseek-flash`。模型 ID 可在页面临时改，也可在 `.env` 设置相应的 `*_MODEL`。Qwen 默认使用阿里百炼新加坡兼容接口；其他地域或 QwenCloud 可用 `.env` 中 `QWEN_BASE_URL` 指向对应 HTTPS 兼容接口。页面密码框可临时覆盖密钥。图片和当前谱仅在主动点击识别／复核时发送给所选服务；页面不会将密钥写入工程。

6/8 拍使用 `"meter":[6,8]`。每小节为六个八分音符单位（等于三个四分音符），通常按 3+3 分组。不要把 6/8 凑成六个四分音符。4/4 三连音用下文的 tuplet 字段，不能以普通八分音符冒充。


## 三连音：必须保留，不得展开成普通八分音符

谱面括号/弧线上方或下方的 **3** 是三连音组号，不是第四个旋律音。每组连续三个等时值的音符或休止符均写相同的 `tuplet` 对象：`{"id":"t001","actual":3,"normal":2}`。不同组必须使用不同 id；组 ID 不能和小节、音符、连线 ID 重复。当前支持同一小节内三音等时值组，支持休止符，不支持跨小节组、混合时值组或附点组三连音。遇到这些未支持情况，写 issues，不得去掉三连音标记伪装成准确转写。

- `base` 仍依据可见减时线：一条线为 8，两条线为 16，无线为 4。
- 实际时值 = 普通时值 × 2/3。三个八分三连音合计一个四分拍；三个四分三连音合计两个四分拍。
- 同一小节内可以混合普通音符和多组三连音。只给括号覆盖的三个音加 tuplet，不能全曲统一乘 2/3。
- 三连音不是 `slur`。若还存在独立的圆滑线/延音线，则另写 spans。
- 6/8 的普通 3+3 八分分组本身不是三连音；只有明确印出三连音标记才添加 tuplet。不得为了避免编码三连音而把图片上的 4/4 改成 6/8。

例如原图一拍 `3 3 3`，都是一条减时线，括号标 3：
```json
{"id":"m-triplet","repeatStart":false,"repeatEnd":false,"notes":[
 {"id":"nt1","degree":3,"base":8,"octave":0,"dots":0,"tuplet":{"id":"t001","actual":3,"normal":2}},
 {"id":"nt2","degree":3,"base":8,"octave":0,"dots":0,"tuplet":{"id":"t001","actual":3,"normal":2}},
 {"id":"nt3","degree":3,"base":8,"octave":0,"dots":0,"tuplet":{"id":"t001","actual":3,"normal":2}}
]}
```
上例是小节结构片段，不是完整 JPU。如果一节四组八分三连音，共 12 音，准确合计 4/4 的四拍；不能读成六拍。

## 补充规则与能力边界

1. 无简谱旋律、只有前奏六线谱的区域：不把品位数字转成旋律，不用全音休止符假装读出了前奏。仅转写可见的简谱区，在 issues 说明省略区域；源图唱段从哪一行开始写入 source 记录。这样音频全曲和视觉唱段存在前奏偏差，须另行对齐。
2. 多段歌词逐行设 verse；重复演唱保留印刷反复，不复制音符来硬展开。支持的第一/第二结尾写顶层 `endings:[{"id":"e1","number":1,"fromMeasure":"m001","toMeasure":"m002"}]`，number 当前为 1 或 2；其他编号写 issues。
3. 印刷换行可在该行第一个小节加 `breakBefore:true`。建议小节加 `source:{"page":1,"row":2}` 便于回查；page、row 为 1 起始的来源定位，不是乐谱小节编号。
4. 延长横线不是新音高：按已有时值/延音线规则编码；一字拖多音时不要重复填字，不要把三连音括号当成延音线。
5. 当前 base 只支持 1/2/4/8/16、dots 只支持 0/1、octave 支持 -2 至 2。32 分、双附点、五/七连音、变拍号、自由节奏、D.C./D.S./Coda 及复杂嵌套反复尚无完整执行表示，必须记录问题，不能静默丢弃。
6. 中途换和弦的精确拍位当前不能可靠由图片字段渲染，写 issues。和弦按实际发声保存，指型按 guitarNotation 显示；不能一部分和弦移调、一部分保留指型。
7. 输出前逐节检查三连音组成员、总拍数、歌词引用、八度点和边界。先按实际分母和 2/3 比例算拍数，再回看原图；不按容量补造休止符。原图真实弱起、尾节和缺图应写 issues。

局部复核时也必须在 updates[].notes[] 保留 `tuplet`，包括休止成员；组用新且全谱不重复的 id。只能整组重读，不能把其中一个成员改成普通音而保留其余两个成员。

输出前必须逐项验证 lyrics.noteId：存在、degree 不为 0、verse 为整数1–4、同一 noteId+verse 唯一。三连音中的 0 也是休止符，不能因为带 tuplet 就挂歌词。若歌词印刷位置无法确认，在 visionReview.issues 中保留文字及小节位置，不得把字随便挂在附近休止符上。图片导入器会把误挂休止符的歌词保留在 importSource.pendingLyrics，并显示待定位问题；这不代表原模型 JSON 已正确。
