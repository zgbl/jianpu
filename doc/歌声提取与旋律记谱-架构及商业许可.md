## 2. 系统架构和数据走向

```text

   ├─ librosa pYIN：人声 → 基频轨迹
   ├─ 能量过滤 / 稳定音高 / 起音分段 → 候选音符
   └─ result.json：原始时间、MIDI 音高、稳定度、速度建议
```

第一次安装依赖和下载模型需要联网。依赖、模型准备好后，当前处理代码在本机执行，不向第三方发送歌曲。文件服务和音频接口使用同一个 Node 服务，没有另开推理端口。

人声分离和音高分析放在两个 Python 进程，便于隔离 PyTorch 推理资源。速度估计使用自己的短时能量自相关；本机此前 `librosa.beat_track` 在真实样本中出现原生进程崩溃，因此现版没有采用它。

## 3. 人声为什么能从伴奏里提取出来

HTDemucs 是训练好的音乐声源分离模型，不是简单的左右声道相减或频率滤波。它结合波形域、频谱域的编码/解码结构，并以跨域 Transformer 交换信息，预测不同声源的音频。官方介绍见 [Demucs 项目说明](https://github.com/facebookresearch/demucs)。

当前选择 `htdemucs`，不是 `htdemucs_ft`、六声部模型或自己训练的模型。模型会估计 drums、bass、other、vocals 等声部；我们只拿 `vocals` 输出。**仅取人声不会省掉其他声部的内部推理计算。**

模型权重缓存为 `.cache/torch/hub/checkpoints/955717e8-8726e21a.th`。精确模型映射、文件 SHA-256 和来源记录在 [model-provenance.json](/Users/tuxy/Codes/Github3/Music-JianPu/doc/license-evidence/model-provenance.json)。

### 关键代码 A：实际的人声分离

代码入口：[audio/separate.py](/Users/tuxy/Codes/Github3/Music-JianPu/audio/separate.py:14)。下列是当前函数正文：

```python
def separate(source,destination):
    torch.set_num_threads(min(4, os.cpu_count() or 2))
    mix,sr=sf.read(source,dtype='float32',always_2d=True)
    model=get_model('htdemucs').cpu().eval()
    audio=torch.from_numpy(mix.T.copy())
    reference=audio.mean(0);mean,std=reference.mean(),reference.std().clamp(min=1e-8)
    with torch.inference_mode():
        stems=apply_model(model,((audio-mean)/std)[None],device='cpu',shifts=0,split=True,overlap=.25,progress=False,num_workers=0)[0]
    vocal=(stems[model.sources.index('vocals')]*std).numpy().T
    peak=float(np.max(np.abs(vocal)))
    sf.write(destination,vocal/max(1,peak),sr,subtype='PCM_16')
```

| 参数 / 操作 | 实际含义 |
| --- | --- |
| `get_model('htdemucs')` | 读取官方预训练模型；首次可能下载权重 |
| `.cpu().eval()`、`inference_mode()` | CPU 推理，不训练，不保存梯度 |
| `mix.T` 和 `[None]` | WAV 的「时间 × 声道」转为模型所需「批次 × 声道 × 时间」 |
| `(audio-mean)/std` | 归一化输入，使不同响度输入更稳定；标准差设最小值避免除零 |
| `split=True`、`overlap=.25` | 长音频分块，块之间 25% 重叠以减轻接缝 |
| `shifts=0` | 关闭随机平移多次预测，减少计算量 |
| `sources.index('vocals')` | 按声部名称选人声，避免假设固定声部下标 |
| `*std`、峰值限幅 | 恢复尺度；当前代码只乘回标准差、不加回均值；超过满幅时缩放以避免写 WAV 削波 |
| `PCM_16` | 输出可直接试听的 16 位 WAV |

这是本次“人声听起来提取得很好”的主要来源。**人声声部不等于领唱独立声部**：和声、合唱也可能保留，混响和伴奏泄漏仍可能存在。

## 4. 从歌声变成音符

人声分离只得到音频。随后用 pYIN 估计每帧基频，才能形成旋律。[librosa pYIN 官方文档](https://librosa.org/doc/0.11.0/generated/librosa.pyin.html)。

### 关键代码 B：音高跟踪和伴奏泄漏过滤

来源：[audio/transcribe.py](/Users/tuxy/Codes/Github3/Music-JianPu/audio/transcribe.py:122)。

```python
sample_rate, hop = 16000, 256
mono = librosa.resample(vocal.mean(axis=1), orig_sr=sr, target_sr=sample_rate)
f0, voiced, probs = librosa.pyin(mono, fmin=65.4, fmax=1046.5, sr=sample_rate,
                               frame_length=1024, hop_length=hop, fill_na=np.nan)
rms = librosa.feature.rms(y=mono, frame_length=1024, hop_length=hop)[0]
voiced &= rms[:len(voiced)] >= max(.0008, float(np.max(rms)) * .025)
if args.mode == 'mixed':
    mixed_mono = librosa.resample(mix.mean(axis=1), orig_sr=sr, target_sr=sample_rate)
    mixed_rms = librosa.feature.rms(y=mixed_mono, frame_length=1024, hop_length=hop)[0]
    voiced &= rms[:len(voiced)] / (mixed_rms[:len(voiced)] + 1e-8) >= .04
```

16 kHz 上每隔 256 样本分析一次，即约 16 ms 一帧；1024 样本窗口约 64 ms。检测范围约 C2–C6。`f0` 是频率 Hz，`voiced` 表示有音高帧，`probs` 是有声概率，不能解读为音符正确率。

能量门限过滤极弱残留，混音模式再检查人声与原曲的 RMS 比例。它们是经验阈值，不能证明每个保留帧一定来自主唱，过严也可能漏掉轻声演唱。

### 关键代码 C：稳定音高和形成候选音符

入口：[pitch_events()](/Users/tuxy/Codes/Github3/Music-JianPu/audio/transcribe.py:26)。核心计算如下：

```python
good = voiced & np.isfinite(f0) & (confidence >= .65)
raw[good] = 69 + 12 * np.log2(f0[good] / 440)
midi[good] = np.rint(raw[good]).astype(int)
stable = median_filter(midi, size=5, mode='nearest')
stable[~good] = 0
```

440 Hz 对应 MIDI 69（A4）。频率先转连续 MIDI，再取最近半音；五帧中值滤波缓和颤音引起的来回跳动。不可靠帧重新置零，不凭空填成有音高帧。

随后将连续相同音高分组，只保留至少 75 ms 的候选片段；根据人声起音把重复同音分开；同音之间 55 ms 以内的短暂掉帧可合并。输出包括 `start`、`end`、`midi`、`confidence`、`centsDeviation`。这里保存的 confidence 是片段平均有声概率；音分偏差反映与量化半音的偏离，不是人工核对后的错误率。

### 混音分离失败时的处理

[audio/transcribe.py](/Users/tuxy/Codes/Github3/Music-JianPu/audio/transcribe.py:108) 中，`mixed` 模式必须先成功生成 `vocals.wav`，否则报错，**不会回退到整首混音取音高**。`solo` 模式才会跳过分离，前提是用户明确选择清唱或独奏输入。

这避免了失败时把吉他或贝斯音符填进旋律，但不能消除分离成功后的伴奏泄漏。

## 5. 从音符时间到简谱文件

入口：[src/transcription-score.js](/Users/tuxy/Codes/Github3/Music-JianPu/src/transcription-score.js:15)。这部分是项目自己的排谱逻辑，能独立于分离模型继续使用。

```javascript
const beatSeconds=60/bpm,unit=beatSeconds/4;
// unit 是十六分音符对应的秒数。
const start=Math.max(cursor,Math.round((e.start-origin)/unit)+phase);
// 按用户确定的 BPM 和第一音拍位，把时间量化到网格。
```

现版以第一候选音符为时间原点，第一音拍位由用户修正；前奏的实际无声长度不会自动排成完整休止小节。每四分拍对应四个网格单位，空隙补休止，跨小节长音拆开并加延音线。调号自动建议仅在 C/D/E/F/G/A/B 七个大调候选中选择，不是完整调性分析。

`pitchToDegree()` 将 MIDI 转为 1–7、八度和升降号；现版半音用下方自然音级加升号表示，保留音高但未必给出音乐学上最佳的等音拼写。SVG 渲染器画出高低音点、减时线、附点、延长音和连线。

`.jpu` 是 JSON，格式标识 `jianpu-melody`、版本 2，不是加密或专有二进制。识别生成的音符示意：

```json
{
  "id": "示意音符ID",
  "degree": 1,
  "octave": 0,
  "base": 4,
  "dots": 0,
  "pitchMidi": 60,
  "sourceTime": 2.08,
  "confidence": 0.94,
  "centsDeviation": 8.1
}
```

`result.json` 保存未量化候选音符和音高轨迹；`.jpu` 保存可编辑乐谱和来源元数据。因此修改 BPM、调号、拍号时可以直接重新排谱，不需要再跑耗时的人声分离。现版限制为 2/4、4/4、最多 200 小节、上下各两组八度，三连音、自由速度和自动歌词识别尚未实现。

仅内部运行或后端运行通常不涉及向客户交付 FFmpeg 二进制，但这是分发义务的区别，不能解决前述权重用途限制。编解码相关专利也不由开源版权许可一并保证，需要按销售地区和实际启用功能评估。

### 7.4 音乐内容、项目设计和自己的代码

软件开源许可证不授予歌曲录音、曲谱或歌词的发布权。用户自己的原创录音可按其权利使用；商业歌曲的人声文件、转录谱面、试听样本若要公开或销售，需要单独确认音乐内容权利。训练数据的使用权也必须包含所需的训练及商业用途。

目前界面、任务调度、音符后处理、JSON 文件格式和 SVG 编辑流程是本项目编写的代码；没有引入 Demucs-GUI、UVR 的界面，也没有使用商业模板或下载其设计图。但当前项目没有为自身代码设置完整的发布许可证/贡献者协议。第三方依赖的版权仍归其作者；不能写成项目拥有这些模型和库的全部版权。

本次核查的是代码、权重、依赖和已有来源，不是全面的外观设计、商标或专利检索，不能据此保证“任何知识产权风险都没有”。产品品牌和素材需要独立确认；AI 辅助生成代码/设计的权利也应按适用服务条款、贡献者合同及当地法律处理。

## 8. 可实现的商业路线

| 路线 | 做法 | 需要解决的主要问题 |
| --- | --- | --- |
| 获取授权 | 向有权授权者取得当前权重商业使用及分发许可 | 明确桌面/云服务、销售地区、期限、再分发范围 |
| 替换模型 | 保留任务接口、pYIN、排谱和编辑器，更换明确允许商用的分离权重 | 核查代码与权重各自许可证、来源；用歌曲集回归测试效果 |
| 自行训练 | 利用许可允许的模型代码，使用有相应授权的多轨数据训练 | 数据许可、训练成本、效果评估；不能只复制现有权重改名 |

工程上最容易保留的是 `vocals.wav` 接口：只要新的分离后端输出同样采样格式的人声 WAV，后面的音高跟踪、排谱和编辑器可以继续使用。

## 9. 怎样重现、检查和继续开发

在项目根目录运行；现有环境已准备好的机器不需要重复下载：

```sh
npm run audio:setup   # 新机器安装 Python 依赖、获取官方科研权重
npm run dev           # 由使用者启动服务
```

浏览器打开主页，选择「听歌记谱」标签。先取 15–30 秒有人声片段，试听分离人声，再核对识别旋律和节奏。

直接运行处理器（写入一个新的输出目录）：

```sh
.venv-audio/bin/python audio/transcribe.py \
  --input /绝对路径/歌曲.mp3 --output /tmp/jianpu-audio-check \
  --start 30 --duration 30 --mode mixed
```

`vocals.wav` 检查声部分离效果；`result.json` 检查候选音符；前端排谱后再检查 `.jpu`。必须区分“人声听起来干净”“音高正确”和“节奏正确”三项指标，不能用一项代替另外两项。
