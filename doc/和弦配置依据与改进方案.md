# 和弦配置依据、排版与本次实现

## 先说明旧版的问题

旧版并没有“按旋律配吉他和弦”。它读取已有 guitar.wav（没有则 other.wav，再没有则 clip.wav），提取谐波、校准调律、计算 CQT chroma；对整小节音类取均值，与十二根音 × 大三、小三、属七、大七、小七共 60 个模板作点积。Viterbi 对换和弦收取 0.12 代价，因此容易长时间保持同一和弦。没有 Do、贝斯、旋律重音、句尾或进行的评分，没有独立验证实际吉他声部。这解释了不合理的 A7 长驻等现象，旧结果只能叫伴奏和声候选。

## 产品上区分两个目标

1. 原曲和弦识别：恢复录音中真正的和声，音频证据优先。不能为了漂亮的进行硬改。
2. 吉他伴奏配置：为旋律建议一个容易弹、连贯的和弦方案，可能与原曲不同。

本次实现的是“音频证据优先、旋律与流行进行辅助”的候选配置，并没有承诺逐小节恢复原曲。

## 本版信息流与权重（代码实际值）

已有伴奏音频 → 谐波提取 → 调律校准 → CQT 音类。
已有 bass.wav → 低音区 CQT → 根音支持（权重 0.08）；低音也可能是经过音或转位，不作为唯一根音。
已校准的小节时间轴 → 每小节两段窗口（前半、后半） → 每段整体音类 70% + 开头 20% 时域的音类 30%。以此强调强拍附近；它仍依赖小节起点，尚未独立修复错误小节线。

`audio/chords.py` 给每段全部 60 个模板的声学分数，不只保留三项。`src/chord-harmony.js` 进一步评分：

| 因素 | 权重/规则 |
|---|---|
| 伴奏模板及贝斯证据 | 主分数，权重 1 |
| 和弦所有组成音在 Do 的大调音级框架内 | +0.07；相对小调以 6 为主音，不改变简谱1 |
| 旋律和弦音占比 | 最高 +0.05；按观测音长加权，窗口开头的旋律音权重加倍 |
| 常见进行中相邻级数 | +0.055，软先验 |
| 七和弦复杂度 | -0.025，避免泛音误推七和弦 |
| 同一和弦连续超过两小节 | 每多半小节 -0.09，软惩罚 |

32 路 beam search 保留上下文，单段最多十个备选。同一小节两段选中相同和弦时合并，因此每小节最多两个标记。不是完整进行模板强制套用：本版利用的是进行中的相邻转移，尚未实现多句段落级模板匹配。

旋律辅助只使用有绝对 MIDI、源时间的观测音；同源连音去重。短经过音贡献小于长音。当前碎音与休止仍影响旋律质量，所以旋律权重较低。音符不是和弦音也可能是倚音、挂留、经过音，不能因此直接否定和弦。

## 进行库

用户提出的 4536、4536251 已加入，按大调框架解释为 IV–V–iii–vi、IV–V–iii–vi–ii–V–I；3、6、2 通常为小三和弦，不是数字根音全用大三和弦。

另外加入 1564、6415、1645、1625、251、15634145。这是常用初始词库，不是歌曲答案；借用和弦、副属、转位及转调仍须音频支持，不能全部吸回调内。

资料：[Open Music Theory：流行/摇滚和声与常见循环](https://openmusictheory.github.io/popRockHarmony.html)介绍 1645/1625、6415/1564 及卡农类进行；[Hooktheory：旋律与和弦结合](https://book-one.hooktheory.com/section/combining-chords-and-melody)作为旋律和声关系参考；[Hooktheory：七和弦](https://book-two.hooktheory.com/section/seventh-chords-in-music)说明七和弦与解决倾向。4536/4536251 是本次用户指定的先验。算法与系数由本项目编写，没有复制网站歌曲和弦数据库。

## Do、实际音高与 Capo

“校准 Do”只改数字音级，录音、MIDI 音高不变。因此实际音高和弦字母不应该统一升降。正确更新：对同一批绝对音高候选，在新 Do 下重新计算调内、旋律、进行评分，更新自动方案，记录 `chordConfiguration.do`。如果音频证据仍支持原和弦，字母可以不变。人工和弦保留。

“整曲移调”和“Capo 指型和弦显示”是另一种操作：前者改绝对音高，后者按 Capo 从实际和弦换算指型。当前和弦只显示实际音高，本次没有新增整曲移调或指型显示，不会重复加 Capo。

## 排版

通常四小节，符号密集时三小节；增加升降号所需水平留白，禁止为了塞四小节压缩字距；增加歌词与下一行和弦的垂直间隔。不同音符量的小节采用不同宽度。和弦放在所在半小节的时间位置上方。最后一行、手工指定换行可不足三小节。

## 操作与验证

刷新看新的排版。新后台分析需用户在原终端停止后重新 `npm run dev`，再点「识别和弦」。校准 Do 会使用保存的全候选重新评分，无需重复计算音频。点选小节后「改和弦」可人工替换本小节标记。

数据保存到 `score.chordAnalysis`（原始候选）和 `score.chordConfiguration`（评分版本与权重）、`score.chords`（显示方案）；工程归档包含 `chords.json`。重排小节时旧时间标记可映射，但应重新识别以使用新的窗口证据。

后续重点：重拍邻域搜索、句尾解决、重复段一致性、独立识别模式与伴奏建议模式、贝斯转位、sus/add9/借用和弦，以及人工锁定某个半小节。不要用换和弦规则掩盖小节时间轴错误；两小节换一次与每小节最多两个是本产品默认建议，不是音乐定律。

本次实际运行：工程当前人工锁定 Do=D（保留用户选择），77 小节拆成 154 个半小节窗口；新分析后合并为 108 个和弦标记。23 行，每行三或四小节。未逐小节试听验证 108 个标记是否为原曲真实和弦；没有按参考图片硬编码 G 或固定进行。95 项测试通过，其中包括校准 Do 后自动候选重新评分、MIDI 不变、人工和弦保留、半小节合并与显示。现有服务确认加载 1=D 及更新标记；新 HTTP 分析任务需用户重启后台后验证。
