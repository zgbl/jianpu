# 和弦配置依据与改进方案

更新：2026-10-05。当前按谱算法：`current-score-melody-v4`。

本文记录代码已实现的规则、可调参数及限制；后续计划另列，不能把功能测试通过当作专业编配质量已验证。

## 1. 三种操作，输入不同

| 操作 | 输入 | 行为 |
|---|---|---|
| 按当前乐谱配和弦（默认） | 当前音符、谱面时值、调号、小节 | 浏览器本地生成配法建议，不调用音频接口或大模型 |
| 从原曲识别和弦（参考） | 当前小节的录音时间范围、分离伴奏声部 | 识别原曲伴奏候选，是另一条路线 |
| 确认并更新和弦 | 已有和弦、C/G 指型、Capo | 只转换显示字母，不生成新和弦 |

两种自动方法会替换现有自动和弦，保留人工和弦，目前不自动融合。按旋律配和弦不能唯一还原原曲编配。

## 2. 默认半小节粒度

设置可选“半小节（相同则合并）”和“整小节”；默认半小节。

- 4/4 的正常小节：前两拍、后两拍分别评分。
- 6/8 的正常小节：前三个八分音符、后三个八分音符分别评分。
- 音符跨过中点时，按与两段重叠的谱面时值分配贡献，不复制整段权重。
- 两段选中同一和弦则合并；不同则保留两个标记。
- 换和弦有 **0.04** 的软代价，避免无意义地频繁切换；同和弦另有 **0.015** 的小幅奖励。
- 不跨小节合并记录，便于每小节显示、编辑和定位；允许连续多个小节使用同一和弦。

当前按“名义小节长度和实际音符总长度中的较大值”划分窗口。拍数有误的草稿可能因此改变中点，应先校对节奏。3/4 若选半小节，分界为 1.5 拍；可以改为整小节。

## 3. 音高与时值取自当前谱

音类计算：

```text
音类 = (当前 Do 的半音位置 + 音级偏移 + 升降号) mod 12
音级偏移：1→0，2→2，3→4，4→5，5→7，6→9，7→11
时值 = 64 / base × 附点倍率 × 三连音倍率
附点倍率：1 或 1.5；三连音倍率：2/3
```

四分音符为 16 单位，八分为 8，十六分为 4。每个分析窗口起点上的新音权重乘 1.5，其余倍率为 1；跨中点的延续音不自动当作中点的新起音。

不使用旧识别的 `pitchMidi`、`sourceTime` 或 `sourceEnd`。八度不改变音类；目前未加入声部位置、音域或可弹性评分。

0、`reviewReason: "unresolved-gap"` 和 `manualSuppressed` 音符不参与匹配。其他有音级的不确定音目前仍按正常权重参与；没有依据 `pitchStatus` 或识别置信度降权。歌词、倚音不参与评分。

和弦绑定当前 `measureId`，段落位置用 `startTick/endTick`，显示不依赖录音秒数。因此添加前奏不会让新配的和弦沿旧录音时间错位。

## 4. 常规候选：三和弦与七和弦

以 `1=C` 为例：

| 类别 | 自动候选 |
|---|---|
| 调内三和弦 | C、Dm、Em、F、G、Am、Bdim |
| 常规七和弦 | Cmaj7、Dm7、Em7、Fmaj7、G7、Am7 |

其他 Do 相应移位；候选使用十二音类名称表，可能采用等音降号拼写，尚未完全按调号统一拼写。

**7、maj7、m7 属于常规和弦，不算用户所说的复杂和弦，不受扩展比例滑条限制，也没有复杂度扣分；另受独立的七和弦比例上限约束。** 为防止短暂经过音触发七和弦，候选七音的加权时值占比必须达到 **20%**。这是目前的简单证据门槛，还不是非和弦音功能分析。

减三和弦有 0.12 的简洁性扣分。当前未自动加入小调属和弦、次属和弦、借用和弦或转调；Do 仍使用大调音级模板，这会限制小调歌的配法。

### 普通和弦中的七和弦比例

新增独立滑条“普通和弦中七和弦上限”，范围 **0%–60%**，默认 **30%**。分母是自动生成的非复杂和弦（三和弦及常规七和弦），分子是其中的7、maj7、m7；9、11、13和人工固定和弦均排除。它是硬上限，不强凑到所选比例。

序列搜索记录普通七和弦数量，预留后续三和弦所需的配额，不把歌曲开头机械地限制为只能用三和弦。局部旋律分筛选中保留最佳三和弦作为配额受限时的替代。重复和弦合并后再次按谱面标记数量检查：若超过上限，优先把七音证据最弱的七和弦简化为同根音、同大/小性质的三和弦，并重新合并。结果提示实际数量、比例与所选上限。

设置随工程保存，也随重新定Do的按谱重评保留。改变滑条后需再次点击“按当前乐谱配和弦”；新配法支持撤销。短谱按整数配额向下取整，例如只有一个普通和弦时，30%或60%都不足以允许一个七和弦。

## 5. 扩展和弦比例上限

滑条范围 **0%–60%**，默认 **30%**，调节的是对扩展和弦的偏好强度；自动配出的扩展和弦另有 **40% 硬上限**。调节后再次点击“按当前乐谱配和弦”才重新生成。人工固定和弦不计入比例，也不受自动建议上限影响。

| 设置 | 含义 |
|---|---|
| 0% | 不自动加入九、十一、十三等扩展候选；三和弦、常规七和弦照常可用 |
| 30%（默认） | 适度考虑有旋律证据的扩展候选 |
| 60% | 更积极偏好有旋律证据的扩展候选；结果仍不超过40% |
| 40% 实际比例 | 自动配出的九、十一、十三和弦最多占自动配弦窗口的40% |

目前从常规七和弦扩展出 9、11、13 候选，并要求所有组成音属于当前音阶。例：Cmaj9、Dm9、Fmaj9、G9 等；不代表所有根音上的同名扩展都符合当前调。

候选还须满足：七音加权占比至少 20%；新增扩展音的合计加权占比至少 20%。扩展候选的局部分数扣 `0.04 × (1 − 比例偏好)`。七和弦本身不计入复杂比例。

偏好作为序列搜索的软目标，偏好超过40%时按40%计算；每个超过有效目标的窗口额外扣 0.2。实现按超额数量的增量计分，不把同一超额重复惩罚。搜索过程中会硬性拒绝使自动扩展和弦比例超过40%的路径。

比例偏好不会硬凑数量：缺少旋律证据时，实际比例可以低于设定值。结果提示实际比例，按生成前自动分析窗口统计；相同和弦合并后的标记数量不作为分母，人工和弦不计入。

自动候选还必须存在于 C/G 吉他指法图库并通过组成音校验。图库没有可用指法的冷僻和弦不会由自动配法选出；图库内的 Gbm、Gbm7 使用等音 F♯m、F♯m7 按法，按弦发声音高仍符合标注和弦。

“扩展/复杂”和“不协和”不完全相同：这个滑条不是声学不协和度控制器。借用三和弦和次属三和弦也不因离调就自动算复杂。

## 6. 旋律分为主，流行进行只加一点权重

局部旋律支持度：

```text
支持度 = 属于候选和弦组成音的音符权重总和 / 所有有效旋律音符权重总和
局部分数 = 支持度 − 减和弦扣分 − 扩展候选扣分
```

先仅保留与本窗口最高局部分数相差不超过 **0.18** 的自动候选。人工固定选项不受过滤影响；最佳三和弦作为七和弦配额的安全替代保留，即使与最高分相差超过0.18。

例如 C 调整小节 `1 3 5 1`，四个四分音符权重为 24、16、16、16；C 支持度为 1，Am 为 56/72，F 为 40/72。这是和弦音覆盖评分，不是概率或准确率。

算法沿当前窗口顺序进行 48 路束搜索，选总分最高的序列。不是完整穷举，不能保证理论最优。

| 软奖励/代价 | 当前值 |
|---|---:|
| 相邻根音级数在流行模板内部相邻出现 | +0.03 |
| 保持相同和弦 | +0.015 |
| 换和弦 | −0.04 |
| 命中长度大于三的模板的前三项，尚未完整命中 | +0.01 |
| 完整模板命中 | +0.025 × 模板长度，最多 +0.15 |

进行库：

```text
4536、4536251、1564、6415、1645、1625、251、15634145
```

数字是和弦根音的音级。例如 4536 通常对应 IV–V–iii–vi；不是旋律数字，也不是四个大三和弦。

- 流行进行在相近配法间提供小幅偏好，不能强制要求歌曲使用模板。
- 半小节模式中，一项代表一个分析窗口，不是必定一个整小节；相同和弦未先压缩再匹配。
- 相邻奖励不自动把模板末尾连回开头。
- 同一步完整命中多个模板，只奖励最长一项，不叠加开头三项奖励；不同结束位置仍可分别获得奖励。
- 完整命中记录存于 `chordConfiguration.progressionMatches`。

这不是句子级和声结构分析，还没有主副歌、句尾解决、重复段或反复展开逻辑。所有权重均为经验值，未经专业编配数据集标定。

## 7. 人工和弦、空小节与更新

人工和弦不被自动结果覆盖。若同小节有多个人工和弦，全部保留；当前搜索只把最后一个作为该小节各窗口的固定选项，因此还不能正确分析多个人工半小节锁定的衔接。

没有可用旋律且没有人工和弦的窗口目前留空，并清空前后进行记忆。不自动沿用上一和弦，也不顺延进行。**这确实可能让原本有伴奏的休止段出现空白，是待改进项，不能称为音乐正确行为。**

按谱生成通过编辑器应用、保存、支持撤销。改完音符后需要再点按钮，普通音符编辑不自动重算和弦。现有 Do 重标流程会按新谱重评，保留粒度和比例偏好；人工和弦保留。

## 8. C/G 调吉他指法图库

在调性/Capo/和弦面板里提供：

- “显示吉他指法图”开关：在谱面和弦上方显示参考图，可取消，不改变旋律。
- “C / G 调吉他和弦图库”：折叠区域，可切换 C 或 G 图库。

标准调弦，左到右为 **6弦→1弦：E A D G B E**。○为空弦，×为不弹；1食指、2中指、3无名指、4小指，粗线为横按；高把位标起始品。

图库在 C/G 两个调下都覆盖常用拼写的12个根音的大、小三和弦，另含七和弦、add9、9、部分11和13指法。开启谱面指法显示后，每个谱面和弦都显示对应指法图；尚无可靠图时明确写“指法待补”，不留空白。部分常用指法直接保存，其他在有限品位/跨度内搜索。检查按弦发音是否属于和弦、是否具备必要音、是否在四手指与跨度范围内；普通标签默认根音在最低实际发声音。

扩展指法可能省略五音或中间扩展音，保留根音、三音/悬挂音、七音和最高标注扩展音；悬停可看省略提示。图中指法仍需实际弹奏确认，不保证是唯一或最顺手的按法。

Capo 指型模式下，先把实际和弦换成显示字母，再取图库；品位相对 Capo。实际和弦模式按显示实际和弦取图。图库外或不支持的标签提示“指法待补”，不会伪造图。其他调可先选择 C/G 指型及 Capo。

## 9. 音频参考功能仍独立

`audio/chords.py` 合并已有 piano、guitar、other 提取谐波和音类频谱，加入 bass 根音证据；没有有效伴奏时回退原曲。按当前录音小节时间分两段，裁到音频范围，候选平滑后再评分。

该分支的音频模板、旋律辅助、七和弦扣分等参数不同于本文按谱分支。它依赖音频与谱面的时间对齐，不是默认按谱配法的隐藏步骤。按谱比例滑条目前不控制此分支。

## 10. 对 Claude 建议的判断与后续顺序

| 建议 | 判断及当前状态 |
|---|---|
| 候选过窄，需小调属、次属、借用和弦 | 同意；常规七和弦、部分调内扩展已补，变化音触发的 E/E7、V/ii、V/V、♭VII 等尚未实现 |
| 休止窗口需要和声延续 | 同意；计划在有前后依据时保留“推测”来源，不能把推测冒充已识别；当前仍留空 |
| 半小节粒度与换和弦代价 | 已实现，默认半小节，可改整小节，相同合并 |
| 短F容易让G变G7 | 已增加七音占比门槛；还需要经过音/解决方向分析；七和弦不归为复杂类别 |
| 进行奖励太大 | 单次完整命中已封顶0.15，小于局部过滤线0.18；但序列奖励可多次累计，不能因此声称绝不会改变选择 |
| 不确定音应降权 | 同意；当前尚未实现，不应把有声概率当音高正确率直接套权重 |
| 先建立评测集和基线 | 同意；功能测试不是编配评测 |

下一阶段优先：

1. 收集约20首具有旋律与和弦标注的 C/G 样例，覆盖大小调、半小节变化、休止和借用和弦。标注必须与实际版本、Capo、反复展开、时间粒度一致。
2. 对比当前算法、无进行奖励版本、逐窗口局部最高分、固定1564基线。记录时值加权和弦匹配、根音匹配、明显旋律冲突，并做人工听感审核。
3. 功能等价需人工规则或审核；**C与Am不是普遍等价**，可以部分替代也不能一律算正确。原谱也只是一个可接受编配，不是唯一答案。
4. 扩展变化音证据触发的次属/借用候选，解决小调属和弦缺失；加入不确定音降权。
5. 加入休止段和声延续与人工半小节锁定，再补足强弱拍、乐句、非和弦音、重复段一致性。
6. 逐步引入可弹性与声部进行，比较推荐方案，而不是只扩大候选集。

## 11. 代码与数据

| 文件 | 职责 |
|---|---|
| `src/chord-harmony.js` | 按谱候选、半小节评分、进行和比例偏好、序列搜索 |
| `src/chord-workflow.js` | 两种操作及进度、结果反馈 |
| `src/key-workflow.js` | 粒度、比例滑条、指法开关和图库；偏好保存到工程 |
| `src/guitar-fingering.js` | C/G 图库、组成音与指法检查、SVG |
| `src/render.js`、`src/layout.js` | 半小节位置、指法图留白和谱面显示 |
| `src/guitar-notation.js` | Capo 指型显示转换 |
| `tests/melody-harmony.test.js`、`tests/guitar-fingering.test.js` | 编配规则和图库验证 |

`chordAnalysis` 保存 method、granularity、color、seventhLimit；`chordConfiguration` 保存权重、命中和实际比例；`chords` 保存实际和弦标签、当前小节ID、startTick/endTick、旋律支持度和来源。支持度不是准确率。现阶段尚无经过标注歌曲集验证的编配准确率数字。
