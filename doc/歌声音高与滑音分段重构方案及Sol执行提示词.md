# 歌声音高与滑音分段重构方案及 Sol 执行提示词

日期：2026-10-02（用户时区）。本轮交付方案，不改业务代码、不修改工程。

## 1. 结论与边界

需要重构“连续音高 → 音符事件”这一层。停止以逐帧半音取整后的相同整数连续段定义音符。正确顺序应是：保留连续基频观测 → 检测音的稳定核心及重新起音 → 联合解释滑音、颤音和换音 → 对整个音符估计目标音高 → 最后映射十二平均律、节奏与简谱。

用户关于滑音被错误切分的怀疑有明确代码依据，但不能据此断言全部半音/全音错误来自滑音。基频检测错误、八度混淆、分离声部污染、合唱以及歌词错位仍需分别验证。稳定地测错一个音，后处理无法凭空恢复真值。

目标是还原录音中的主唱旋律，不是强制贴合网上简谱。参考谱可以帮助核验相对音程，须确认版本、歌词对应和改编情况；不能拿当前自动歌词位置直接当音符对应关系。

### 已确认的实现缺陷

1. `audio/pitch-segmentation.py` 在识别稳定核心之前调用 `np.rint(raw)`。滑音穿过50、51、52，会先制造数个“音符”，后续局部平滑无法可靠撤销。
2. 按整数段是否含 `.65` 帧作保留条件，再删除短于75ms片段。阈值会同时产生假音和假休止，并不能区分快速真音与滑音。
3. 同音两侧相同的局部修补能处理部分抖动，处理不了单向滑入/滑出。降门槛后的上一轮10秒对照事件从19增到21，不能称为音符准确率提高。
4. `librosa.pyin` 返回的第三项是 `voiced_prob`，本地文档定义为有声概率。现代码把它命名为 confidence 并用于“音高可靠”判断；有声强不代表基频正确，也不代表属于主唱。
5. pYIN使用2048样本/16kHz，即128ms窗；RMS仍1024样本，即64ms。hop虽同为16ms，感受范围不同。长窗可能跨越音符边界，不应简单补偿固定64ms，也不能认定所有偏差都是固定延迟。
6. 首先应用voiced与能量硬掩码，会丢失后续解码需要的低置信证据。无基频观测不等于乐谱休止。
7. 唱同音的新音节并不一定出现明显能量凹口。目前仅靠能量下降+onset切分，可能把重唱合并；反过来每个辅音都切一音也错误。

## 3. 架构：把观测、音符解释、排谱分开

```
已保存原曲 / vocals.wav
  → 带统一时间坐标的观测缓存
    ├ 连续f0 / 有声概率 / 周期性或谐波证据
    ├ 短窗能量 / onset / 可选声学音节边界
    └ 可选第二检测器的独立轨迹
  → 稳定核心候选 + 起音/终止候选
  → 带持续时间约束的音符序列解码
  → 未量化音符事件（目标音高 + 表现性滑音）
  → 未量化MIDI试听与局部A/B确认
  → 既有节奏量化、小节、Do映射、歌词和弦层
```

第一阶段继续使用现有 pYIN，重点检验音符解码层；同时预留第二检测器接口。不要在同一轮同时改调号、小节和全部歌词，否则无法判断改善来自哪里。

## 4. 连续观测与时间基准

保存浮点MIDI（`69+12*log2(f/440)`）或cents，直至音符目标音高确定后才取整。缓存字段明确区分 `voicingProbability`、`periodicity`、`pitchReliability`、`sourceReliability`，缺失的概率为null，不伪造统一置信度。

保存模型/库版本、采样率、hop、窗长、center/padding、音频哈希、区间和参数。缓存key包含这些信息。原有 `confidence` 保留兼容，标记其实际含义，禁止悄悄改写旧结果。

统一所有特征的秒坐标。音高和onset允许不同窗长，但必须显式时间对齐。在已知起音的合成数据上验证延迟；不能通过整曲统一加减一拍修复。

对相同音频比较64、96、128ms分析窗，hop先保持约10–16ms，记录频率稳定度和边界误差。低音与快速音分别评估，别只以窗口更大为“更准”。

录音整体调律偏移单独估计：从多个可靠稳定核心计算对100 cents周期的稳健偏移，记录置信范围；证据不足默认0但明确未确认。不能为每个短音独立估计调律，也不能通过整体偏移掩盖局部错音。

## 5. 从稳定核心推断目标音

### 5.1 稳定核心不是“原始曲线一条直线”

对连续cents轨迹计算局部稳健中心、离散程度、趋势和有效观测覆盖率。颤音可以幅度较大，但围绕相近中心周期摆动；滑音的中心随时间持续移动。用多尺度局部拟合/中值趋势估计中心，保留原始轨迹，不以单帧导数阈值判定稳定。

初始可比较80/120/200ms上下文；这些只是待标定参数，不是规则答案。短音不足一个长窗口时，用短尺度、谐波证据、起音证据综合评分，不按固定最小时长一刀切。

### 5.2 音符目标音高

对候选事件内的稳定核心，用加权中位数或Huber稳健拟合估计 `pitchCenterCents`。权重来自可靠观测、趋势稳定性和声源证据；过渡帧不参与或低权参与。不要固定“只取中间50%”，稳定核心可能偏后，短音也可能没有明显平台。

事件定音时才计算最近半音，同时保存未取整音高、偏差及第二候选。靠近半音分界或多个检测器冲突，输出低置信候选供对比，不强吸到当前大调。

### 5.3 滑音怎样处理

示例：轨迹从 D 滑过 D♯ 后稳定在 E，且D/D♯没有独立稳定核心和重起音证据，默认形成一个目标为E的音，前部记为唱入滑音。不是D、D♯、E三个普通音。

如果 D 和 E 都有持续的独立中心，即使中间连着唱，也应形成两个音。真实装饰音、倚音、快速经过音进入短音候选分支，不因时长短自动丢掉。只有持续滑动、没有可靠核心时保留“目标音不确定”，不强猜终点就是目标。

保存 `coreStart/coreEnd` 与 `performanceStart/performanceEnd`。核心用于定音，表现时间用于音符/歌词起止核对。若直接把音符开始改为核心开始，会把音符和歌词普遍推迟。

### 5.4 颤音和八度

围绕同一中心的颤音合为一个音；不得把每次跨半音边界拆音。±12半音跳变只是倍频/半频候选，只有结合前后稳定性和谐波证据支持才校正；不能无条件把大跳压回去。真实跳进及男女声切换应保留。

## 6. 序列解码，而不是继续叠加局部阈值

推荐用候选边界上的动态规划/半马尔可夫模型，状态包含起音/滑入、稳定核心、滑出、无声、观测缺失。观测缺失与无声分开。

候选边界来源：稳定中心变化、voicing结构、局部能量、频谱起音，可选声学音节边界。允许稳定音直接转移到下一个稳定音，连唱不要求中间先出现静音。

概念评分：

```
总成本 = 稳定核心音高残差 + 不可靠/声源冲突成本
       + 边界证据成本 + 持续时间软约束 + 多切音符成本
       + 跨事件连续性成本
```

全部权重写入配置，以标注数据调参；不凭感觉写死后宣称正确。持续时间和连续性为软约束，不能禁止真短音、大跳、半音和小调。

同音重唱：相同稳定中心也可切为两个事件，但须有重新起音的组合证据。歌词ASR只能提供弱参考，不能“一字一音”，不能让ASR错字决定旋律数量。一字多音和一音多字都允许。

休止符：只有声学证据支持声音实际停止，才在事件层建立静默区间。辅音、低周期性、分离器瞬间空洞可为 `unknown/unvoiced-transition`，不立即打印0。不得把所有空洞全部延长前音。

## 7. 基频本身错误时怎么办

加入可替换检测接口，pYIN为基线，torchcrepe为独立对照候选。两者使用各自参数和有效音域，在稳定核心比较差值；不平均不一致的f0，否则可能合成一个不存在的半音。出现>约50 cents稳定分歧应标注冲突，再检查谱图谐波及声源；50 cents是初始实验阈值。

优先仅对冲突片段运行第二模型，缓存结果，避免整曲重复计算。也测试分离人声与原曲同区间的证据；原曲仅作验证，不能静默把伴奏音当主唱。合唱/重叠声源不满足单音假设时应明确标记，不把换模型等同于已解决。

模型代码、权重和依赖许可证分别核实；这一方案没有授予任何新增依赖商业使用保证。Tony/VOCANO在这里是方法参考，不直接复制其代码进项目。

## 9. 产品验证入口

新增局部旋律核对面板，显示原始连续曲线、稳定核心、滑音/颤音分类、旧/新音符矩形、被排除观测与原因。

三个试听入口并列：提取人声、原始f0合成、未量化音符MIDI。前两者使用原始时间，MIDI使用事件表现时间，不走小节量化。共享区间和指针，能循环同一句。原始f0合成保留缺失帧，音量归一，避免音色/音量差异影响判断。

默认产出建议，显示冲突和不确定区间；确认采用后才更新简谱。用户不需要重新识别整首歌才能比较一个句子。

## 10. 分期与验收

### P0：先把测试真值和诊断做对

- 建立只读10–30秒样本集：本次《小酒窝》开头、同音重唱段、滑音明显段，以及其他歌曲/合成样本。
- 逐句听原录音和分离声部，人工确认稳定核心绝对音高、事件边界、滑音/装饰音；未确认标null。不能用网上数字加一个猜测Do作为绝对真值。
- 修正confidence语义，统一时间坐标，保存原始观测。输出旧方法基线错误清单。
- 先验证原始f0中心是否可信。若稳定核心自身持续错半音，P1切分并不能解决，必须进入P2检测器对照。

### P1：重写音符事件解码

- 连续音高进、稳定核心及音符事件出；延迟取整，滑音归属，颤音中心，缺测/真静音分开。
- 起音、目标音高、终止分别保存，序列级解码，不再以整数run直接排谱。
- 实现局部重识别、未量化A/B试听、版本化候选及确认采用。
- 保留v2作为基线，算法可选择，不自动覆盖用户工程。

### P2：解决稳定基频错误

- 接入第二检测器，做一致性及谱图谐波对照；如果仍不够，再评估专门歌唱音符转录模型。
- 模型选择以本项目真实数据的错误类型、速度和许可证为依据，不以论文总体分数替代本地验证。

### 指标和停止条件

测试必须同时统计：匹配音符的绝对音高误差（含八度）、相邻音程误差、音符插入/删除、同音重唱召回、真休止误报、滑音假音数量、起止时间误差。不能仅统计匹配上的音高，漏掉难音会虚增准确率。

分开报告原始f0核心精度、未量化事件质量和量化后乐谱质量。短音、颤音、连续半音、大跳、长滑音、无核心滑音、同音连唱、强辅音、弱尾音、真静音、声源冲突分别测试。

初步发布门槛（目标，不是已测结果）：关键人工确认短句不再有半音/全音错误；保留集音符音高正确率目标≥95%，且插入/删除不能恶化；报告样本数和匹配规则。音符匹配采用时间单调一对一匹配，匹配成本不能先使用音高把错音排除。起音误差先报告50/100ms两档，不只用一个宽容阈值。达不到就交付错误分析，不通过改Do、吸音阶、删音或重排小节掩盖。

## 11. 可直接交给 Sol 的执行提示词

请先实现本方案P0和P1，预留P2接口。读取并保护当前未提交代码与用户数据。不启停/占用5173，不提交推送。

核心是重构连续f0到音符事件的解码，禁止逐帧半音取整后把整数run当最终音符。区分唱入、稳定核心、收尾、真无声、观测缺失。稳定核心定目标音，表现起止对齐录音；滑音不自动拆普通音，同音重唱、真实短音和八度大跳必须保留。voiced_prob不得宣称音高正确概率，不以当前Do作强制音阶吸附。

先用最新《小酒窝》运行缓存做只读诊断和人工真值清单。参考谱只辅助对照；禁止按歌名硬编码、猜Do或猜八度，禁止把此前五个检测事件未经对齐就认定为参考五个音。

提供局部“只重新识别旋律”任务，复用已有声部；候选未确认不覆盖主谱。提供人声/f0/未量化MIDI同区间试听、指针和旧新对比。工程保存恢复所有候选、版本、观测和人工修改，测试取消及失败路径。

交付代码、合成回归测试、真实录音逐句对照报告、未解决错误和用户操作顺序。若原始f0稳定核心仍错，明确标记P2依赖，不宣称P1已解决识别准确率。
