# VocalParse 实施计划与音频识别调试工作台设计

日期：2026-10-04。项目：Music-JianPu。本文是实施方案；本文中的新页面、接口和文件名均为拟议设计，并非已实现功能。

## 1. 决策与实施顺序

建议先建立可视化调试工作台，再接入公开 VocalParse 模型作为第二路音频识别器。使用同一段人声比较现有 pYIN + 稳定核心 v3 与新模型，保留原始证据和候选版本，由用户确认修改。只有实测收益稳定，才考虑改变默认识别器。

第一轮目标是回答三个问题：错在声部分离、逐帧音高测量，还是音符起止/节奏量化？VocalParse 能否减少半音错误和漏音？提供正确歌词后能否改善逐字对应？第一轮不训练新模型，不需要建设大规模训练数据集。

## 2. 论文原理与可验证证据

论文 [VocalParse v1](https://arxiv.org/html/2605.04613v1) 使用经过歌声任务微调的音频语言模型，联合预测歌词和旋律。它先生成连续歌词，再生成“字—音高—时值”的交错序列，支持提供已知歌词作为条件；模型继承 Qwen3-ASR，训练包含约 2000 小时自动标注歌声。这里的 CoT 指这种两阶段输出结构，不能理解成给任意聊天模型加一句“仔细思考”就获得同等能力。该说明依据论文 §3–§5。

公开的 [AST 格式说明](https://github.com/pymaster17/VocalParse/blob/main/docs/note_tokens.md) 使用 MIDI 音高、十二种普通/附点时值以及 BPM。一字可关联多音，因此可表达同一字唱出多个音的情况。模型内部预测是符号序列；它没有给我们一条可逐帧检查的真实基频曲线。

论文在 Opencpop 上报告音高 MAE：纯音频 0.56 个半音，提供歌词 0.35；相同条件下 ROSVOT 是 0.38。纯音频因此并非在所有条件下都领先。去掉两阶段输出或大规模训练数据后，指标变差，说明效果来自任务训练和数据，不能只归功于提示词。论文也指出固定 BPM、歌词输出不完全一致、教师标注质量和中文评测范围的限制。[实验与限制](https://arxiv.org/html/2605.04613v1#S5)

这些平均误差不能换算成我们工程的正确率，也不能说明所有滑音都能处理正确。模型对歌声的统计学习可能改善目标音推断，但我们必须在用户实际 MP3 上核实。

## 3. 它怎样影响我们的准确率

以下是结合项目问题作出的工程推断，不是论文对本项目的保证。

| 当前症状 | 可能的改善机制 | 仍然必须验证的风险 |
|---|---|---|
| 滑音过程被取整成错误半音 | 歌声模型结合字、邻近旋律和时值推断目标音，而非仅对局部 f0 取整 | 模型仍可能选错目标音；它不提供可替代声学证据的 f0 曲线 |
| 一个字被分成多个碎音，或真实换音被合并 | 字—多音联合结构可能改善分段 | 相同音高的重新发音不能一律合并；必须听清是否再次起音 |
| 多字粘在一个音符下、漏字后整句错位 | 已知歌词条件可减少文本错漏及对应关系的不确定性 | 错误歌词、重复副歌、实际少唱/多唱会误导模型；不能强行填字 |
| 音符起点落到上一小节 | 模型候选可提供另一路音符组织信息 | 真实起音、量化后的拍位、小节下拍是不同问题，仍需分别处理 |
| 半音或八度误判 | 跨字上下文可能限制不合理跳变 | 分离残留和声、谐波、男女合唱仍可能造成错误 |
| 6/8 与 4/4 三连音互相混淆 | 用模型候选辅助判断音符分组 | 公开时值表没有三连音比例，不能直接依赖它解决该问题 |

判断准确率必须分层：绝对 MIDI 是否正确；演唱起止是否正确；谱面时值是否正确；歌词是否对应；调号是否合适。手动定 Do 可以修正数字音级解释，却不会把错误的绝对音高测量变正确。

## 4. 输出能力与转换边界

依照公开 [时值定义](https://github.com/pymaster17/VocalParse/blob/main/docs/note_tokens.md)，普通八分音符是四分拍单位的 1/2，附点八分是 3/4。八分三连音需要 1/3，现有词表没有这个值。对三连音歌曲，不能将模型时值直接吸附为普通八分音符，也不能为了填满小节擅自改拍号。

BPM 也不等于拍号：6/8 的两大拍与六个八分细分，以及 4/4 的四个四分拍，需要在项目的节拍解释层处理。保存 BPM 时必须记录它的单位，不能把附点四分 BPM 和四分 BPM 混用。

模型序列没有原曲绝对起止时间、小节下拍、调号、和弦与完整连线信息。模型时值 × 60/BPM 只能得到名义演奏时长，不能直接当原曲时间。前奏、休止、气口、自由速度和输出错漏都会使累加时间漂移。AP/SP 等气口/静音文字应单独解析；MIDI 0 是实际音高编号，不能未经约定就当作简谱休止符 0。[上游解析代码](https://github.com/pymaster17/VocalParse/blob/main/vocalparse/evaluation.py)

接入时先保存独立候选序列，再建立原曲时间映射，最后生成 JPU。时间没有可靠映射的候选可以显示并校对，但不能伪装成已对齐的播放指针。

## 5. 当前项目可以复用的部分

以下依据 2026-10-04 读取的本地代码。

| 文件/数据 | 当前用途 | 本计划的复用方式 |
|---|---|---|
| `audio/transcribe.py` | 分离、pYIN、v2/v3 候选、节拍分析 | 复用已有 `vocals.wav` 和同一音频片段，不重复分离 |
| `pitch-observations.json` | 逐帧浮点 MIDI、能量、有声判断、概率、处理后 MIDI | 绘制原始音高证据与过滤结果；保留全部帧，不只显示通过阈值的帧 |
| `melody-candidates-v3.json` | 音符候选、v2 对照、诊断和核心 | 展示演唱范围与稳定核心的区别 |
| `audio/stable-pitch.py` | 核心、滑音、调律与候选事件 | 显示 `coreStart/coreEnd`、`pitchCenterMidi`、滑音标记及调律偏移 |
| `src/transcription-score.js` | 声学事件到简谱的转换 | 做适配而非直接灌入未对齐 AST；审查当前十六分网格对三连音的限制 |
| `src/audio-score-cursor.js` | 谱面音符与播放位置映射 | 使用明确转换后的时间；核对现有裁剪偏移约定 |
| 双谱比较、工程版本、手动 Do | 查看与确认候选 | 保留新候选和已编辑版本的区别；确认后再生成修订版 |

当前逐帧步长为 256/16000 = 16 ms。步长只表示采样曲线的密度，不表示检测有 16 ms 的独立时间分辨率；重叠分析窗口仍会把换音边界混在一起。

## 6. VocalParse 接入架构与部署检查

计划流程：

```text
现有工程/原曲
  → 复用人声 + 片段清单
  → VocalParse 常驻推理进程
  → 原始 AST + 结束原因 + 候选音符/歌词关系
  → 时间映射 + 声学证据对照
  → 独立候选谱 + 差异提案
  → 用户确认 → 工程修订版本
```

公开 [单片段入口](https://github.com/pymaster17/VocalParse/blob/main/vocalparse/demo.py) 支持单声道 16 kHz 输入，生成长度默认上限 512。这是输出 token 上限，不能沿用该默认值直接处理整首歌；截断必须显式报告。生产适配应常驻加载模型，避免每个片段重新载入权重。

公开 [批量 API](https://github.com/pymaster17/VocalParse/blob/main/vocalparse/api.py) 已有 `audio-only` 和 `audio-lyric` 条件模式，但使用 `/dev/shm`，不能在当前 macOS 工程中直接照搬。公开 [模型加载器](https://github.com/pymaster17/VocalParse/blob/main/vocalparse/model.py) 当前选择 CUDA 或 CPU，没有自动选 Apple MPS；CPU dtype 与 Apple 加速兼容性也必须实测。

阶段部署选择：优先在有 CUDA 的独立工作进程完成可重复小样本评估；若使用当前 Mac，先建立单样本加载验证，再适配设备与精度配置。不能承诺未经验证的显存要求、MPS 兼容性或实时速度。部署前固定上游 commit、权重 revision、依赖版本，并记录各权重与代码的许可条件。

切片策略为本项目建议：先试 8–20 秒的完整短句，优先在气口处分割；包含滑音/长音的音符不在中间强切。必要的重叠区保留全局时间，按歌词、原曲位置与音高序列合并；重复副歌不能仅因文字相同就合并。每个片段保存独立结束状态，失败片段可重跑。

页面状态必须显示正在加载模型、片段编号、已完成片段数、实际收到的输出量、最后一次进展时间、取消和失败原因。没有 token 事件时只能显示阶段与等待时间，不生成虚假进度。区分超时、输出上限、正常结束、空结果和解析错误。

### 6.1 数据与拟议接口

新增独立候选结构，以下不是 JPU：

```json
{
  "schema": "audio-note-candidates/1",
  "engine": "vocalparse",
  "modelRevision": "固定的权重版本",
  "timeBase": "original-audio-seconds",
  "segments": [{
    "id": "seg-001", "start": 30.0, "end": 42.0,
    "inferenceMode": "audio-lyric",
    "rawAstAsset": "segments/seg-001.ast.txt",
    "finishReason": "eos", "truncated": false,
    "notes": [{
      "id": "vp-001", "midi": 67,
      "quarterBeats": {"numerator": 1, "denominator": 2},
      "lyricUnitId": "char-001",
      "start": null, "end": null,
      "timingStatus": "unmapped",
      "pitchReliability": null
    }]
  }]
}
```

`start/end=null` 表示尚未得到声学定位；必须写明缺失。拍长用有理数，后续可表达 1/3 拍；但不能借这种结构声称公开模型已预测出三连音。原始 AST、解析警告、对齐方法、人工修改都单独保存。

上游解析器会对缺失时值补四分音符、忽略部分孤立/未知 token。工程适配必须将每次补值、丢弃和歌词前后不一致写进警告，避免“能显示”被误认为“准确”。不要把生成 token 的概率、pYIN 有声概率或候选分数直接显示为音高正确率。

拟议接口：创建识别任务、读取任务进度/分片结果、取消任务、读取不可变候选版本、提交人工修改提案、确认提案。所有任务绑定 `projectId/runId/audioHash`；前端收到旧任务返回时不能覆盖新工程或用户已修改版本。

### 6.2 从候选序列到真实时间

先使用歌词建立短句和字的候选匹配，再用原曲位置、音高变化及局部能量建立单调时间映射。目标是确定每个候选音在录音中可能出现的范围，而非把现有错误分段当标准答案。

对齐代价组合歌词匹配、MIDI 差、相对时值和起音证据。允许一对多、多对一、漏音、多音与无映射；同一句在多个时间位置出现时，使用片段位置限制匹配。使用 pYIN 时保留其不可信区间；声学证据不足时不强配。

配准后保存每个音的时间来源与质量等级，拖动候选边界只改提案。名义时值和演唱时间分开：例如附点四分谱面占 1.5 拍，但实际声带振动可能提前结束或拖后。连续同音是否为两个音，需要结合重新起音、字变化和试听，不能仅依 MIDI 相同决定合并。

## 7. 音频识别调试工作台：可行，而且应优先做

用户设想的“像股市图一样查看音高变化”可行。应使用三种同步视图，避免把幅度误当音高：

| 视图 | 横轴 | 纵轴 | 最适合回答的问题 |
|---|---|---|---|
| 波形/能量 | 原曲时间 | 振幅、能量 | 哪时开始发声、哪时变弱、有无停顿 |
| 频谱图 | 同一时间 | 频率或音名；亮度代表频谱强度 | 是否残留伴奏、存在多条谐波、是否有清晰基频结构 |
| 音高曲线 + 音符矩形 | 同一时间 | MIDI/音名，旁标 Hz | 滑音、稳定目标音、半音误差、八度跳变与切分 |

普通波形的纵轴是振幅，不能直接在它旁边画 C4/D4 线来判断音高。频谱中最亮的线也不一定是基频：220 Hz 的音会在约 440、660 Hz 处出现谐波，这是正常结构。主研究视图应是音高曲线；频谱作为检查来源的证据。

### 7.1 页面布局

```text
工程/识别版本/声源 | 播放 暂停 循环 | 时间缩放 | 显示图层
全曲概览波形：框选可见时间窗
局部波形：发声、能量、字边界
局部频谱：可展开，保持同一时间窗
音高主图：半音网格 + 原始 f0 + 校正曲线 + 核心 + 候选矩形
节拍/小节 + 歌词 + 小段简谱
选中音检查面板：各路 MIDI、起止、稳定核心、音分差、原因
人工修改提案：修改前 → 修改后 | 试听 | 确认 | 撤销
```

所有图同步水平缩放和播放指针；暂停允许静止检查。提供“播放跟随”开关，可再次点击关闭，不能强行把正在观察的画面拉走。数据图层均可开关，图例与实际显示状态一致。

纵轴按 MIDI 半音等距，而非 Hz 等距；可在旁边显示 C4 261.63 Hz、A4 440 Hz 等。公式为 `midi = 69 + 12*log2(f/440)`，`Hz = 440*2^((midi-69)/12)`。半音为 100 音分；音分偏差为 `(浮点MIDI - 候选MIDI)*100`。音名轴不随 Do 改变；简谱音级是另外一层解释。

默认只显示三层：原始音高、有声可信帧、当前音符范围。进阶开关再展示调律校正曲线、v2/v3、VocalParse 候选、频谱和过滤原因。低可信帧用淡色点表示；无声/缺失区间断线，不能跨空白插值成真实测量。

### 7.2 每个音的三个范围

必须区分：演唱范围 `performanceStart/End`，稳定核心 `coreStart/End`，谱面拍位范围 `gridTimeStart/End`。滑音可能发生在演唱开始到稳定核心之间；只看音符矩形无法研究是哪一层错了。

音符矩形表示候选起止，内部较深的短条表示稳定核心；水平线表示目标 MIDI，原始 f0 曲线覆盖其上。颜色只表达来源/选中状态，问题用边框、图标及文字标记，不把整谱涂成橙色。

选中后显示：绝对音名、Hz、当前 Do 下的音级、中心音分差、核心散布、有声概率、来源质量是否未知、原始/人工边界及对应字。没有真实概率校准的数据不显示“正确率 95%”。

### 7.3 手工研究流程

1. 在谱面点一个听起来不对的音，工作台定位原曲对应时间，默认显示其前后约一秒。
2. 循环听原曲与人声，可试听目标 MIDI；默认正常速度，慢放必须保持音高并标明处理方式。
3. 判断曲线是否只在开头爬升，中央是否稳定；查看核心是否误落在滑音阶段。
4. 拖左右手柄建立新的候选范围，可进一步圈一个稳定核心；原算法结果仍显示，人工修改可取消。
5. 点击“重新估计选区音高”只生成新候选：汇总可靠帧中心、散布、覆盖率与调律偏差；区间无可靠基频时提示不足，不能按平均值强给音名。
6. 若用户确认是漏音/错音，可加音、拆音、合音或指定 MIDI，预览影响的小节、歌词与连线，然后确认写入新版本。

边界拖动先只改变选区；没有证据时不能假称重新运行检测。逐帧 f0 来源窗口不变，缩短选区仅筛选已有帧，不会提高检测的实际分辨率。需要短窗口重新测量时另起任务，并将结果另列一条曲线。

### 7.4 非专业用户的判断提示

| 看到的现象 | 可以提出的假设 | 下一步 |
|---|---|---|
| 开头斜坡、后面长平台 | 入音滑音；目标可能是平台 | 听核心/全音对照，不拿开头一帧定音 |
| 曲线围绕同一水平线上下摆动 | 颤音 | 看中心是否稳定，别将每次摆动拆成音符 |
| 突然跳约 12 个半音后返回 | 可能是八度误判，也可能真换八度 | 看谐波结构与试听，不自动拉回 |
| 几个长音都偏向同一音分 | 可能整体调律偏移 | 对多个稳定音统计，不能只看一帧 |
| 人声轨能听见第二声部或伴奏 | 分离残留可能干扰 | 切换原曲/人声并看频谱，不仅调分段阈值 |
| 曲线合理但谱面音错 | 可能是核心选择、取整或 Do 解释 | 比较原始 MIDI、目标 MIDI 与调号 |
| 起止合理但小节拍数错误 | 可能节拍/量化问题 | 查下拍、拍号、弱起与三连音解释 |

这套提示用于提出假设；单一图形不能证明原因。参考谱必须确认同一录音版本及移调，绝对音高和相对旋律分开比较。

## 8. 工作台工程与数据约定

建议增加独立 `audioDebug` 页面，引用现有工程的 run 和音频资产；旧工程可读取现有 observation 和候选文件，缺失信息显示“未记录”。不要求重识别整首歌才打开页面。

统一采用原曲秒作为页面时间轴。音频片段数据按明确 metadata 加裁剪偏移，不能重复叠加；分别封装原曲播放器、人声播放器与 clip-relative 观测的转换。用不同裁剪起点的工程验证点击、循环、光标与导出选区一致。

波形存 min/max 多级降采样，不只存均值以免抹掉短起音；音高按可见窗口加载，缩小时仍保留异常点或散布带。频谱使用 Canvas/WebGL 或预计算瓦片，按需计算局部窗口，避免把十分钟高分辨率矩阵一次性转 JSON。

频谱窗口建议提供 1024/2048/4096 的观察选项，显示窗口时长与时间/频率折衷；这是显示分析参数，不等于重新配置识别器。采样率改变后按实际 Hz/时间坐标绘制，避免标签沿用旧参数。

拟新增文件职责：`audio-debug.html/css` 为页面；`src/audio-debug-page.js` 管工程/声源/播放器；`src/audio-debug-chart.js` 管同步坐标与选择；`src/audio-note-review.js` 管提案/确认/撤销；`audio/audio-debug-api.mjs` 管观察数据与选区分析；`audio/vocalparse-worker.py` 管推理；`src/vocalparse-import.js` 管 AST 及候选转换。名称可调整，职责须保持清楚。

人工修改保存 `before/after/reason/baseRevision/audioHash`。调试模式默认不自动改正式谱；点击确认才更新，并检查工程版本冲突。撤销/重做覆盖音高、起止、拆合音、歌词关系及相关连线。局部修改要刷新当前谱与双谱对照引用的工作版本，不能回到最初识别结果。

## 9. 分阶段交付与进入下一阶段的条件

| 阶段 | 工作与交付物 | 完成条件 |
|---|---|---|
| A：现状基线 | 选 3–5 首实际歌曲、15–30 个短句；保存人工参考与现有候选 | 确认同一录音版本、绝对音高及时间来源，覆盖滑音、弱唱、同音重复、气口、三连音 |
| B：调试页 MVP | 波形、半音曲线、原始/核心范围、循环、音名/Hz、选区检查 | 能打开旧 run，统一时间；可开关图层、取消选区和播放跟随；没有隐式改谱 |
| C：可审查编辑 | 修改范围/核心/MIDI、局部估计、差异预览、确认和撤销 | 改动在工程重开后保留，双谱同步更新，撤销恢复相关数据 |
| D：模型小样本 | 固定版本运行 VocalParse，保存 AST、解析诊断、运行成本 | 完成纯音频/已知歌词两种条件；能区分截断与正常结束；失败不丢已有结果 |
| E：时间对齐与候选谱 | 单调局部时间映射、JPU 适配、模型/声学对照 | 无映射不假画精确指针；三连音未知不硬改；结构错漏可人工确认 |
| F：收益决策 | 输出对照报告和代表性错误例子 | 在独立留出片段上确认收益后决定默认引擎；失败则保留为研究候选 |

A/B 可先做，VocalParse 部署验证独立推进。只加载权重与生成输出不算完成接入；能够比较、解释、确认修改并保存工程才算完整工作流。

## 10. 准确率、时间线与体验验收

对照集合不能用现有识别输出作真值，也不能把视觉大模型结果未经校对就当真值。人工参考记录不确定片段；调参用一部分，最终评估用留出部分。

配对音符时允许插入/删除，以时间和歌词位置约束一对一匹配；不能按数组序号比较，因为漏一个音会使后面的音全部错配。报告未匹配音符和匹配覆盖率，防止只统计容易匹配的部分。

核心指标包括：匹配音符 MIDI 完全正确比例；全体真值音符中被正确检出的比例；半音/八度错误数；音符检出 precision/recall/F1；起止偏差中位数与 P90；逐字匹配及漏字；拍长/三连音结构正确率；人工修订次数和耗时。起音容差可先取 50 ms 做对照参数，需对真实样本标定，并同时显示连续偏差，不能只用单一阈值掩盖问题。

拟议决策门槛为项目目标，不是论文数据：留出片段的音高错误数降低至少 20%，检出 recall 不下降超过 2 个百分点，且人工校对总时间降低；三连音组单独报告，不被普通歌曲平均掉。样本太少时仅报告观察结果，不宣布普遍提升。按歌曲汇总，并保留失败样本，避免只挑最好的一句。

界面验收重点：任何开关可再次关闭；点取消不会修改正式谱；输入与现有音符属性的状态清楚；拖边界可以撤销；频谱/低可信点可隐藏；播放跟随可停止；重启后进程中断显示原因；没有真实输出时不声称“正在返回内容”。

## 11. 交给编码模型的执行要求

先实现阶段 B，读取旧工程数据，不更改已有识别结果。优先复用 observation、v3 候选和播放器，完成原曲时间转换、同步坐标、手动选区、循环与明确图例。随后增加阶段 C 的提案确认和完整撤销，再接 VocalParse。每个阶段提供可操作页面与明确验收，不用一轮同时重构音频识别、歌词、节奏与工程存储。

识别代码不得把有声概率等同正确率，不得将缺失音高插值画成观测，不得把 token 截断静默导入完整乐谱，不得强行按四个音符分小节，不得将名义时长当原曲时间，不得为了拍数整齐静默补音。兼容降级或补默认值必须保留可见诊断。

本轮交付为本文档。具体模型部署耗时、当前 Mac 的推理速度、准确率收益，以及工作台视觉效果，都属于下一阶段的验证内容。
