# Do（1）校准：操作说明与验证报告

本次实现方案中的 P0/P1；P2 只保留接口和验证计划。目标是让 Do 可以有依据地分析、核验、锁定，**尚不能保证全自动找准每首歌的 Do**。改变 Do 不会修复原本识别错误的绝对音高或节奏。

## 一分钟操作顺序

1. 在你自己的终端停止旧服务，再运行 `npm run dev`，刷新主页。新增 Python 分析接口需要加载新版服务；本次没有操作你的 5173 服务。
2. 打开已有 `.jpp` 工程，进入识别与编辑工作区。**无需重新分离或识别整曲。** 在谱面工具栏点 **确定 / 校准 Do（1）**。
3. 点 **分析原曲的 Do 候选**。先看前三个候选、时间窗一致率和大小调说明；分数不是准确率，也不会自动改变谱面。可试听候选 Do。
4. 更可靠的办法：在下方旋律时间轴点 **在时间轴圈选**，拖选人声里一个稳定元音，或填起止秒数（从原曲开头算，0.12–3 秒）。点 **循环听此区间 → 测这个音 → 试听测得参考音**。音变化太大或置信度不足会拒绝添加。
5. 根据你已确认的参考短句/听辨，选择 **这个音是几**，必要时指定升降号，再点 **添加这个音级锚点**。换一个不同音级重复一次。不要照抄当前识别谱的数字，否则没有独立校准作用。
6. 两个不同音级推出同一个 Do 后，点 **按一致锚点确认并锁定**。冲突时不会平均，也不会自动覆盖；逐项试听并删除错误锚点。已明确实际 Do 时，也可直接从十二音选项选择并确认。
7. 用工具栏的 **当前小节 MIDI 试听** 对照人声。保存工程包，关闭再打开，检查 Do 的锁定状态、锚点、候选证据和谱面编辑是否恢复。

**本次校准不要点“重新划分全曲”。** 校准 Do 的确认按钮只重标记音级；BPM 按钮仍处理小节和节奏。确认后实际 MIDI 应与确认前完全相同，数字及升降号会变化。

参考谱写实际调时选 **实际调（直接使用）**；只给吉他指型调时选 **吉他指型调**，再填 Capo：E 指型 +3 = G，G 指型 +3 = B♭。已经写实际调就不会再加 Capo。若极低/极高音超过两组八度表示范围，可调整“无八度点的1”组别；越界会报错并保留原谱。

## 实现与数据

| 文件 | 职责 |
|---|---|
| `src/pitch.js` | 十二音/同音异名、统一 MIDI↔音级、纯重标记、KeyMap、已知音级求 Do 与冲突检查 |
| `src/key-workflow.js` | 校准面板、区间选择/循环、测音、候选确认、锁定/解除、Do 专用撤销、取消与工程身份检查 |
| `audio/key_analysis.py` | 已有音频的谐波 CQT chroma、调律、12秒时间窗/6秒步进、24个大小调候选；独立 pYIN 单音测量 |
| `audio/key-api.mjs` | 本机异步分析任务；取消、超时、请求校验；不重跑 Demucs、不调用云端 |
| `audio/project-store.mjs` / `audio/project-archive.py` | `key-analysis.json` 资产注册、校验、白名单与工程包恢复 |

原曲 `clip.wav` 为主，人声/其他伴奏为辅助，贝斯作诊断；各声部来自同一原曲，不能当成独立多数投票。输入原曲 SHA256、参数、方法版本、调律、各窗 chroma 和24候选保存在分析资产。`KeyMap` 在谱中记录 `doPc/referenceDoMidi/tonicPc/mode/status/source/locked/anchors/revision`，锚点带区间、测得 MIDI、可靠度及识别版本关联。工作区记录圈选区间和分析关联，候选不会替换已锁定 Do。

小调默认按 la-based 简谱：例如 A 小调的歌曲主音 A 可写 6，简谱1为 C。候选表分开显示主音、调式和简谱1；确认一个 Do 不代表同时确定了大小调。

旧 `suggestKey` 仅留作诊断对照，生成谱不再用它宣称定调。自动生成未校准谱用明确标注的 C 预览；它不是识别答案，也不是音域异常后的静默回退。旧 `.jpu` v1/v2 可读取，旧 `key` 标为未确认。保持 v2 并新增可选 KeyMap；旧客户端若只支持七个自然调，将不能读取含降调号的新谱，请使用新版程序。`.jpp` 保持 v1，新增允许归档的分析资产。

纯重标记从当前编辑的 `degree/octave/accidental` 还原 MIDI，不用可能过时的 `pitchMidi` 覆盖人工改音。音符/倚音 ID、歌词、连线、时值、音频时间、原始识别元数据及人工边界保留。Do 专用撤销同样只重新标记当前音符；普通谱面历史仍负责原有编辑。

CQT/调律使用既有 librosa 0.11.0；CQT 的 tuning 以频率格为单位，本实现把半音调律值换算为36格/八度的3倍格偏移。参考：[官方 chroma_cqt 源码文档](https://librosa.org/doc/0.11.0/_modules/librosa/feature/spectral.html)。未引入新模型或商业 API。

## 验证结果与限制

- Node 非端口测试：76项通过，覆盖十二个 Do 与等音名逐半音往返、越界拒绝、改音/倚音/歌词/边界保留、MIDI 时间序列和字节一致、旧谱迁移、Capo、锚点冲突、本机接口取消及非法请求、工程重开和 `.jpp` 导入导出。
- Python：十二份实际合成音频逐半音移调，CQT 候选同步移调；24候选和关系小调映射；稳定 A4 测音、静音拒绝及反相立体声选声道通过。该测试证明转换与受控音频行为，不能当成真实歌曲准确率。
- 真实浏览器：沿用现有5173服务，在独立标签中导入 `/tmp` 临时谱，验证 B♭ 确认锁定、撤销、E 指型/Capo 3 得实际 G，无页面错误；未改用户工程。已有服务器尚未加载新增后端路由，因此未在浏览器跑完真实音频分析、锚点测音与工程保存重开全流程；这些后台行为已作隔离测试，用户重启后仍需实测。
- `npm test` 中两个需监听临时端口的服务测试被沙箱 `listen EPERM` 阻止；没有为绕过它启动开发服务。其余测试另行全部通过。

### 《千年之恋》只读诊断

读取当前工程已有原曲与声部，结果仅写 `/tmp`，没有修改源工程或其音频。原识别有102个碎事件，累计音符片段仅约19.04秒，原曲228.173秒；旧算法在这些碎事件上建议 D。这不是 D 正确的证据。

独立分析结果如下。
| 简谱1候选 | 最强调性解释 | 匹配分数 |
|---|---|---|
| Bb | G minor | 0.753551 |
| G | G major | 0.711510 |
| F | D minor | 0.614866 |

有效谐波时间 204.103 秒；原曲分窗首选一致率 34.3%；首/次 Do 分差 0.042041。分析状态仅 `suggested`。输入 SHA256：`adb96fa4babd9360aeed008d530afc40752eaf4608fe5d505ecca25e072308f9`。

**同一录音的真实 Do 尚未人工确认；不把此前猜过的 G、B、B♭、D 当作答案。** 已有谱存在大量短事件和休止，属于另外的旋律/事件切分问题；本次不通过改变 Do 掩盖这些问题。

待人工核验表：开头8小节、主歌、副歌、尾段均标“未确认”；需各取至少两个不同已知音级，核对稳定实际音高、参考谱的实际调/指型调约定，再建立真值。缺少这些标注，目前不能给歌曲 Do 正确率，也不能声称相对音程问题已经修好。

## P2 后续接口与验证计划

分析 JSON 已预留 `p2.intervals/cadences/chords/segments`，KeyMap 预留 `segments`。目前均为空；**未把3–4、7–1关系当成已完成的证据**。

下一阶段在原始可靠基频/频率帧上保存 `{start,end,midi,cents,confidence,source}`，为每个候选算3–4与7–1半音方向、句尾收束及其支持/反例；禁止先吸附到候选音阶再证明自己。参考短句接口应输入音级序列和可选原曲时间范围，使用观测音程对齐，输出匹配区间、移调候选和误差；不得按歌名硬编码。

和声接口输出分窗的低音与和弦候选及置信度；分段接口输出调性变化区间、候选、证据，先建议再确认。逐项做消融：基线chroma → 加半音关系 → 加句尾 → 加和声 → 加参考短句；保留实际改善项。

建立有人工真值的独立留出集，包含12调、关系大小调、五声、无4/7、借用音、转调、重叠人声、静音和强鼓。分别报告 Do Top1/Top3、歌曲主音/调式准确率、拒识率/覆盖率、锚点一致率；验证不能用“全部拒识”获得100%。《千年之恋》人工真值补齐后单列报告，不作为训练时固定答案。
