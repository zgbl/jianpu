## 1. 结论与建议路线

建议采用 **联合识别拍点与小节第一拍的预训练模型 + 多速度层级比较 + 有拍号约束的时间网格 + 人工锁定边界**。不要继续把“低频峰值最强的位置”当作小节第一拍，也不要只在当前检测速度周围继续平均。

先修复速度设置与谱面不同步的问题，再接入新模型。否则识别器改善后，用户仍可能看到旧谱、听到另一套节拍。

首选试验 Beat This!，以原曲为主要输入，鼓和贝斯作为辅助证据。保留现有算法作为对照与降级方案。模型是否实际改善这两首中文歌，必须通过人工标注的真实小节验证；本方案没有声称已经验证成功。

## 4. 新的识别架构

```text
原曲（统一音频时间轴） ─→ 拍点 / 第一拍模型 ─→ 帧级证据与候选事件
已有鼓、贝斯 ─────────→ 质量评估、辅助起音与相位证据
人工 BPM、拍号、边界 ────────────────────┐
                                         ↓
                    多层级候选 + 拍号约束解码
                                         ↓
                      RhythmMap（唯一生效时间网格）
                                         ↓
        音符重新分小节 / 谱面游标 / 节拍器 / 对照播放 / 工程保存
```

### 4.1 模型选择及部署

首选 **Beat This!** 官方实现，先使用 `final0`、CPU、`dbn=False` 建立基线。官方提供拍点与第一拍输出，以及可供自定义解码的帧级接口。其代码和公布的权重声明采用 MIT；默认推理不要求 madmom。资料：[官方仓库与接口说明](https://github.com/CPJKU/beat_this)、[推理实现](https://github.com/CPJKU/beat_this/blob/main/beat_this/inference.py)。

本地推理即可；首次下载模型与运行时调用云 API 是两回事。实施时固定依赖版本、模型版本和 SHA-256，明确记录模型缓存路径，保留许可文件。先用 CPU 验证依赖，再实测这台 Mac 的可用加速后端；不要承诺未验证的 MPS 兼容性或处理速度。

先用官方完整音频推理与后处理输出做 A/B，不要第一天同时重写模型和解码器。若仍有漏拍/层级问题，再用帧级概率加入下节的自有约束解码。模型输入以原曲为主，分离鼓与贝斯的证据权重需验证，不能直接假设分离声部更准确。

不把 madmom 预训练模型作为默认商用依赖：官方注明模型和数据通常是 CC BY-NC-SA 4.0，与代码许可不同。单用解码算法与加载其模型要分开审查。[madmom 官方许可说明](https://github.com/CPJKU/madmom#license)。MIT 声明也不替代整个依赖链和用户音频权利的核查。

### 4.2 先决定正确的拍子层级

保留多个候选 `(BPM, 拍号, 第一拍相位)`，不能先把一个 BPM 当真再排谱。

1. 从模型拍点、第一拍间隔和现有周期候选生成速度提议。
2. 比较原速度、半倍、两倍、三倍、三分之一；有证据时纳入 3:2、2:3，去重并限制合理范围。
3. 首版拍号限 2/4、3/4、4/4。用户选定拍号是硬约束；自动拍号模式才比较多个拍号。
4. 联合比较拍点概率、第一拍概率、稳定性、跨段连续性、人工锚点一致性。贝斯起音只作辅助，不能规定第一拍必须最大声。
5. 对不同速度使用按时间或预期拍数归一化的评分，兼顾遗漏高概率拍点和无证据插入的代价。直接累加峰值会偏向高 BPM，只奖励命中又可能偏向低 BPM。
6. 分别检查主歌、副歌、间奏和尾段；候选差距小则显示“速度层级待确认”，提供带重拍节拍器的候选试听。

6/8 暂不悄悄当作 3/4：以后支持时显式区分四分音符 BPM 与附点四分音符脉冲，以及每小节 6 个八分音符。当前格式尚不完整支持，应明确提示。

### 4.3 完整网格不等于检测峰值列表

模型事件只是证据；输出必须包含音乐拍序号。漏掉一个起音，不应让音乐时间少一拍。

固定速度候选下，令四分音符周期 `T = 60 / BPM`，用 `q_i ≈ round((t_i - a) / T)` 提议整数拍序号，再通过单调匹配排除重复、误检和不合理跳跃；稳健拟合 `t_i ≈ a + q_i*T`。缺号位置补出网格拍，并标记 `inferred`。不要继续用检测列表下标拟合。

需要更强解码时，使用 beam search / Viterbi：状态包含拍内相位、拍号中的拍位、周期候选；每经过一拍推进拍位，到小节末回到第一拍。观测弱时允许网格继续前进，代价上升而不是把几小节并成一小节；人工锁定边界禁止违反。引入新解码器前应先与官方后处理作对照，避免复杂度增加却无法证明收益。

静音、散板、长间奏不能假装全部已确认。输出覆盖范围、外推区间和置信类别；无证据区间可延续已确认速度，但显示为推断。

### 4.4 固定速度与变速分开处理

对多数稳定录音，默认使用固定速度。先解决层级，再在多个有证据的 10–20 小节窗口估计周期，使用正确拍序号稳健汇总，检查首中尾的漂移。均匀小节由时钟保证，不必每小节都检测到一次响亮重音。

通式：`每小节秒数 = 60 / 四分音符BPM × 拍号分子 × 4 / 拍号分母`。
例如 120 BPM 的 4/4 为 2 秒；3/4 为 1.5 秒。BPM 与第一拍锚点必须共同决定网格。

如果多个远端锚点无法被单一周期解释，报告冲突并提供“分段速度”，不要以全曲平均抹掉真实变速，也不要自动改成人工未同意的新 BPM。首版可以先只支持固定速度和冲突提示，分段速度后续实现；数据接口提前容纳它。

## 5. 一份 RhythmMap 管所有时间

当前 DOM 控件、result.rhythm、workspace.rhythm、score.transcription、score.tempo 各有参数。改成候选与已应用两层：控件只是待应用参数；所有播放和显示读取同一个已提交的 RhythmMap revision。

建议新增工程级版本结构，以下为结构示意，不是可直接导入的实际歌曲数据：

```json
{
  "version": 2,
  "revision": "rhythm-revision-id",
  "timeBase": "source-audio-seconds",
  "clipStartSeconds": 0,
  "sourceRunId": "recognition-run-id",
  "mode": "fixed",
  "bpmUnit": "quarter",
  "meter": [4, 4],
  "segments": [{"startSeconds": 0, "endSeconds": 120, "bpm": 120}],
  "anchor": {"timeSeconds": 2, "quarterPosition": 0, "barNumber": 1},
  "constraints": [],
  "beats": [],
  "bars": [],
  "evidence": {"modelId": "model-and-hash", "candidates": [], "coverage": []}
}
```

- beats 每项保存 `quarterPosition`、`timeSeconds`、`beatInBar`、证据分数、`detected/inferred/manual`；bars 保存起止秒、编号、锁定状态。
- 音频时间统一为原曲秒；现有 clip 相对秒只在迁移入口加 clipStart，禁止各播放组件反复自行加减。
- `timeToQuarter` / `quarterToTime` 提供唯一双向映射；界面、游标、量化、节拍器共用。
- 检测 BPM、用户指定 BPM、已应用 BPM 分字段，不互相覆盖。UI 明示当前生效值、候选值和来源。
- MIDI 在固定速度首版使用同一已应用 BPM；将来有分段速度，必须输出 tempo events。纯谱试听若允许独立改速度，应明确“试听速度”，不能冒充原曲同步。
- 音符保留不可变的原始音频事件 ID 与 start/end；谱面时值、跨小节拆分和 ties 是其派生表示。新插入音符明确标为没有源音频锚点。
- `.jpp` 保存候选、人工约束、已应用网格、当前谱与版本关系。旧工程迁移只读旧字段形成一个 revision；不能因打开文件而自动重识别覆盖用户编辑。

## 6. 人工介入应成为可靠约束

保留原地编辑，提供两个清楚动作：

1. **此处是第 1 拍**：固定相位；不擅自改速度。
2. **这两个边界之间有 N 小节**：选择原曲时间 t1、t2，并输入实际小节数 N。小节长度 `(t2-t1)/N`，四分音符 BPM 为 `60 × N × 分子 × 4/分母 / (t2-t1)`。用第三个远端边界检查漂移。

N 必须由用户确认，不能沿用当前错误谱面的“小节编号差”。当前合并三小节的错误会被这种自我引用继续传下去。边界应可在连续音频时间轴上放置，不能只允许落在已有音符起音处；第一拍可能是休止、延音或根本没有新起音。

拖动小节线记录其明确的音频时间和音乐序号。硬锁定的人工边界不能因贝斯峰值自动移动；互相矛盾的硬约束必须报冲突。若用户选择自动微调，则另设允许偏移量，不用隐含权重表示“锁定”。

“重新划分全曲”先生成预览：显示新旧 BPM、小节数、边界差异、受影响编辑。应用是一个可撤销事务。保留用户音高、歌词、多字同音、删除和插入操作；只重新分组与拆分跨线音符。不要重新调用原始识别数据生成全新 ID 后，就把旧人工修订归档当作已经保留。

## 8. 实施顺序与验收

### 阶段 A：先让手工参数真正可控

统一已应用网格、修复编辑后跳过更新的路径、后端传递拍号、引入显式锚点和重排事务。验收：120 BPM、4/4、已知起点，连续边界必须间隔 2 秒；3/4 必须 1.5 秒。改过歌词和音高后仍能应用、撤销、保存再打开，参数、谱面、节拍器一致。

### 阶段 B：接入新模型并比较真实歌曲

增加独立模型适配模块，输出原始 beats/downbeats 与覆盖信息。保留旧结果并生成对照报告，不立即覆盖工程。先比较官方后处理；必要时进入多层级与约束解码。无法分辨层级时提供候选试听和两点标定，不输出虚假的 100% 正确率。

### 阶段 C：保留修订的全曲重排
