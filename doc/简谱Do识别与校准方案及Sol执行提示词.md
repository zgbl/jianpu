# 简谱 Do（1）识别与校准：项目审计、实施方案、Sol 执行提示词

日期：2026-10-01。本文是实施方案，尚未实现或验证新算法。依据当前源码、只读检查的《千年之恋》工程和文末官方资料整理。本次只新增此文档。

## 1. 要达成的结果

用户需要可信的 `1=…`，而不是一个总会返回答案的猜测器。建议交付 **十二音完整支持、独立音频证据分析、可解释候选、已知音校准、确认后锁定** 五部分。

“任意录音全自动、永远正确”不能作为工程承诺：仅有几个音的旋律、关系大小调、五声音阶、转调和混合调式都可能存在真实歧义。可执行的产品标准是：自动建议有验证数据；证据不足明确待定；人工有直接、可重复的办法确认；重新分析不能覆盖已确认结果。

必须同时纠正一个前提：**绝对音高和相对音程可以先于 Do 识别。**频率先决定实际音高，Do 决定它被写成几。改变 `1` 不应改变原声、旋律音程或 MIDI；只会改变音级名称。若一个乐句的升降走向已错，换调不能把它修好。选调分析也不必等待全曲转谱完全准确，可以直接使用原曲的和声证据。

推荐工作流：

```text
导入原曲 / 打开已有工程
  → 从已有原曲、人声、伴奏提取调性证据（无需重复分离）
  → 候选 1 + 各段证据 + 待确认状态
  → 用户确认候选，或“圈一段声音，指定它是几”交叉校准
  → 锁定简谱 1
  → 按同一绝对音高重新标记数字，保留节奏、歌词、小节线
  → 人声与 MIDI 对照，单独处理旋律识别错误
```

## 3. 先把“哪个音是 1”定义清楚

### 3.1 三个概念分开保存

- **实际音高**：如 MIDI 59 / B3。来自音频或人工改音，与调号分开。
- **歌曲调性主音与调式**：如 A minor。主音是乐句和和声的中心，不必是最常出现的音。
- **简谱 Do**：`1` 对应的音类。在常用的“6 为小调主音”记法中，A 小调可写 `1=C`，主音为 6。不能把分析器返回的 A minor 直接变成 `1=A` 后仍套大调数字模板。

首版保留现有数字音阶模板 `[0,2,4,5,7,9,11]`：大调采用主音为 1；小调采用 6 为主音，`doPc = (tonicPc + 3) mod 12`。和声/旋律小调的变化音用临时升降号表示。其他记法/调式首版允许人工确定 Do，不自动强行解释。关系大小调分析不确定时，如果两个候选映射到同一个 Do，可以单独确认 Do、保留 mode 待定。

### 3.2 半音关系如何真正参与分析

对候选 Do 为 `k` 的大调数字模板：

```text
1 = k      2 = k+2    3 = k+4    4 = k+5
5 = k+7    6 = k+9    7 = k+11   （全部 mod 12）
3→4：+1 半音；7→高音1：+1 半音。
```

检查**音频里确实观测到的稳定相邻音**是否支持这些位置；结合 7→1 是否出现在收束处、和声是否回归主和弦等证据。不能先强制吸附到某候选音阶，再宣称它满足半音关系——那是循环论证。

半音证据是有则加分、缺失则未知：五声音阶旋律可能根本没有 4、7。一个半音对还可能属于不同候选调，不能独自锁定 Do；经过音、借用和弦和临时变化音也不能一律判错。小调分析采用对应调式关系，不机械要求“小调主音前一定存在自然大调式导音”。

### 3.3 Capo 和参考谱不能重复移调

参考谱必须声明 `keyMeaning: concert | fingering | unknown`。

- 若标的是**指型调**：实际调 = 指型音类 + capo 品数（mod 12）。G 指型加三品是 B♭，E 指型加三品是 G。
- 若标的是**实际调**：Capo 只解释指法，不能再加一次。
- 用户给的图同时写有 `1=G`、`E-G Capo=3`，可能已经区分 E 指型与 G 实际调。此前对话把它直接解释成 G 再升三品，并不充分。必须确认标记约定及与录音的对应关系，不能把 B、B♭ 或 G 任一个未经验证地写成这首歌真值。

录音是否移调也要另记。参考谱只提供线索，不可压过录音中测出的可靠实际音高。

## 4. 自动分析：可实施的两阶段算法

### 4.1 阶段 A：先交付完整候选与校准，不急于自动盖章

复用已有 Python、NumPy、SciPy、librosa 0.11.0，新增 `audio/key_analysis.py`。输入已有 `clip.wav` 为主，`vocals.wav`、`bass.wav`、`other.wav` 为辅助。鼓声不作定调主证据。缺失分离文件时允许仅分析原曲的谐波成分；不要重新运行 Demucs 才能判断 Do。

具体步骤：

1. **检查声源质量。**检查静音比例、时长、削波、有效频谱/音高覆盖。立体声先检查相位抵消风险，不无条件左右相加。静音帧不能归一化成响亮证据。
2. **估计微调偏差。**分析相对 A440 的小幅偏离，保存 cents；它只修正半音栅格，不可用“微调”偷偷吸收整半音/三半音的移调。可靠度不足采用 0 cents 并标记未校准。
3. **抽取独立 chroma。**原曲取谐波成分，以 CQT chroma 形成十二音类证据。伴奏和人声独立归一化，保留每路质量；不能原曲加人声加贝斯投三票，因为它们来源相关。
4. **分时间窗。**首版可用 12 秒窗、6 秒步长作为可调初始配置；不依赖当前还不可靠的小节线。静音和低质量窗口跳过，主歌、副歌、尾段分别报告；窗口长度由实测调整。
5. **生成至少 24 个候选。**十二个 tonic × major/minor；对 profile 做可比较的归一化相似度，输出所有候选得分。额外比较音阶内外能量，但音阶内音多只能说明调族，不能区分关系大小调。
6. **按质量稳健汇总。**先归一化每个有效时间窗，再汇总；限制一个长音、一个很响的片段或大量重复副歌支配全曲。保存跨窗口排名和冲突，不只输出最高分。
7. **首版全部为建议。**没有标注集和校准报告前，候选分数不是“正确概率”。显示排名和证据强弱，不伪造 95% 置信度。

这条独立分析链可绕开当前碎音符估调的缺陷，但不保证解决旋律本身的错音。不能把更换一个 chroma API 宣布为识别已准确。

### 4.2 阶段 B：加入真正与调中心有关的序列证据

在阶段 A 的基线、校准界面与测试均可用后，再增加：

- **人声稳定音程。**从连续帧生成分析用稳定片段；保留颤音/滑音及可信度，短暂失跟踪作为 unknown。检查有方向的半音关系、回归中心音的倾向；不把所有变化都切成新音符，也不以降低置信度阈值替代建模。
- **乐句收束。**用人声音量/停顿、长音和已有歌词时间作边界候选。多个乐句收尾比单个末音可靠；不能规定最后一个音必是 1。ASR 文字可能错，时间也只作辅助。
- **和弦序列。**在伴奏 chroma 上比较大小三和弦、常见七和弦及 `no-chord`，用时序平滑减少逐帧跳变；保留和弦候选。根音、转位与最低音不是同一件事；贝斯只帮助消歧。终止式/主属关系作软证据，不要求流行歌必须出现 V–I。
- **分段一致性。**连续多窗出现稳定不同候选时报告疑似转调。首版可让用户分段确认 Do；如果尚未支持谱内调号变化，则阻止“整曲已确认”的错误状态，而不是把整曲强压成一个调。

评分结构可以是 `S = wH*和声匹配 + wM*旋律匹配 + wI*音程序列 + wC*收束 + wB*低音辅助 - 冲突惩罚`。各特征先归一化，缺失证据不记为失败；权重由开发集选定、在留出集验证。不能把随手设的权重和 softmax 当作音乐正确率，也不能因三种相似 chroma 算法同意就称为三份独立证据。

自动推荐进一步标为“高把握”前，需要足够有效时长、跨段稳定、候选分差和真实验证集支持。阈值与结果一起版本化；不满足时仍可人工确认。

## 5. 能落地拿准 Do 的人工校准

### 5.1 用户知道某个音是几：从实际声音反算 Do

这是首版必须提供的功能，不依赖全曲自动选调正确。

1. 在人声时间轴上圈一个稳定发声片段，循环播放；显示频谱/音高候选与参考钢琴音。不要只允许点已识别的谱面数字，因为那个数字可能已经错了。
2. 用户指定：“这段唱的是 3”（也可 1–7，并指定临时升降号）。使用区间内可靠基频的稳健估计；若候选冲突、和声重叠或无稳定音，要求换片段，不自动取最响频谱峰当基频。
3. 用公式求 Do：`doPc = mod(round(midiStable) - [0,2,4,5,7,9,11][degree-1] - accidental, 12)`。例如可靠测到 B，用户确认它是 3，则 Do 为 G。这个例子不预判当前歌曲。
4. 再选另一乐句的不同音级验证，最好第三处也一致。相互冲突时逐项列出各锚点推导的 Do，不能平均成一个调、不能静默删除不合意锚点。
5. 用户试听并确认后锁定。若已知道实际 `1=…`，可直接选择十二音中的一个，标为人工指定；“人工指定”和“多锚点交叉验证”区分显示。

锚点还记录声源、原曲秒数、估计 cents、指定音级、证据质量和用户操作来源。同一低八度/高八度误判不影响 Do 的音类，但会影响谱面八度，必须单独提示。误把泛音当基频可能改变音类，因此不以单个 FFT 峰替代可靠基频估计。

### 5.2 用户有正确简谱片段：用多音验证参考谱与录音

允许输入短句，如 `3 3 2 3 1'`，并圈选对应录音。按真实半音偏移计算参考音程，与录音稳定轨迹做受约束的时序对齐；允许少量装饰音、重复音和时间伸缩，但明确限制跳过比例和匹配代价。

枚举十二个 Do 和合理八度，输出最佳匹配、次佳差距及逐音残差。必须同时看匹配覆盖率和相对音程，不允许靠大量跳过错音得到完美分数。若只是整体移调，残差应近似同一个常数；若各音需要不同偏移，报告“旋律提取/片段对应不可靠，无法用改 Do 修正”。不能把匹配上的参考音硬写入识别结果，再称为识别成功。

参考乐句优先用于验证与辅助校准，不能硬编码《千年之恋》的歌名、时刻或目标 Do。手工改错音应是单独、可撤销的操作。

## 6. 数据、界面与持久化

### 6.1 唯一权威的 KeyMap

建议工程级 `KeyMap` 记录“已应用的记谱基准”，`KeyAnalysis` 记录候选，两者分开。以下仅为接口示意，数值是示例，不是歌曲结论：

```json
{
  "version": 1,
  "revision": "key-revision-id",
  "timeBase": "original-audio-seconds",
  "status": "confirmed",
  "source": "manual-anchors",
  "doPc": 7,
  "doSpelling": "G",
  "referenceDoMidi": 67,
  "tonicPc": null,
  "mode": "unknown",
  "notationPolicy": "major-degree-template",
  "tuningCents": 0,
  "locked": true,
  "anchors": [],
  "analysisRevision": "analysis-id",
  "segments": []
}
```

`doPc` 采用 C=0…B=11。`doSpelling` 决定 F♯/G♭ 等显示；`referenceDoMidi` 指无八度点的 1，避免参考谱八度约定不同造成混淆。首次兼容旧谱采用 `60+doPc`，不悄悄把旋律升降八度。`tonicPc`、`mode` 不确定时可以为空/unknown；确定简谱 Do 并不等于证明了全部调式。

状态至少有 `unknown / suggested / confirmed / conflict`。`KeyAnalysis` 另外保存算法/参数/输入哈希、有效覆盖、每窗候选、候选分差、质量、证据范围和错误。所有分析时间转换为原曲秒数，明确 `clipStart`；不能有的锚点用片段秒、有的用原曲秒。

旧 `.jpu` 仍需兼容读取，但已有 `key` 只标“旧工程记谱基准，未核实”，不自动当作人工确认。新字段的兼容/版本策略须写清：若仍用 v2 扩展，旧客户端不支持降号 key 时明确提示；若升级版本，提供迁移和新旧导入测试。不要向旧格式悄悄写入它无法理解的数据。

### 6.2 改 Do 必须是纯重标记事务

新增统一 `src/pitch.js`，集中音名、十二音类、MIDI↔数字/八度/升降号转换。编辑器、转谱、试听和导出共享，消除多份 `KEYS`。

更改 Do 时：先从**当前编辑后的音符**和旧 Do 求绝对 MIDI，再编码到新 Do；不能拿旧 `pitchMidi` 覆盖用户已经改过的音。新增源音高与编辑音高的明确字段/语义，避免把原始观测也覆盖掉。

验收不变量：音符 ID、时长、绝对音高、原曲时间、歌词关联、连线、小节边界保持；只更新音级/八度/临时记号及 Do 元数据。旧 accidental 必须先清除再写新值，避免 `Object.assign` 留下旧升号；倚音一并处理；越界应报错或扩展音域支持，不能改成 C。**这条操作不再调用整曲 `transcriptionToScore` 重排。**

另设“把歌曲移调”功能才允许改变实际发声音高，两者命名和操作分开。

### 6.3 界面与保存

- 谱面固定工具栏显示 `简谱 1：待确认 / G（已锁定）`；点击展开候选、十二音选择、校准、参考谱片段输入。显示清晰状态，不把“自动建议”伪装成确定调号。
- 原曲、人声、MIDI 试听与暂停始终在手边。候选 Do 的琴音/主和弦是辅助试听，不能证明正确；单纯重标记后的整曲 MIDI 应完全相同。
- 新分析完成先显示候选；应用需独立事务，可撤销并保存历史。人工锁定不被改 BPM、重分析、切换页面、重开工程覆盖。
- `unknown` 时仍可听原声、看音高轨迹/绝对音名。可预览明确标“试用 1=X”的候选谱，但不伪装为确认结果。旧谱保留且标未核实。
- `.jpp` 保存 KeyMap、候选、校准锚点与音频证据关联；再打开不必重新跑模型。为 `key-analysis.json` 等新增资产更新服务器白名单、注册、归档校验与恢复路径；缓存大矩阵可以不打包，但复现所需配置和摘要必须保存。

## 7. 给 Sol 的实施顺序和验收门槛

### P0：先把可信的人工校准和数据基础做出来

1. 新建统一十二音转换模块；支持升降调号；清除自动 C 回退；写 MIDI 往返及所有十二音测试。
2. KeyMap、锁定、旧谱迁移、纯重标记事务、撤销与工程保存恢复。
3. 实现原声区间选取/循环、“此音是几”校准、多个锚点冲突检查、十二音人工选择；不必等自动模型改善才交付。

### 必须通过的验收

| 项目 | 判定标准 |
|---|---|
| 十二音往返 | 在支持音域逐 MIDI、逐 Do 测试，数字编码后还原 MIDI 精确相同；F♯/G♭、B♭等均通过 |
| 改 Do | 用户改音、临时记号、倚音、跨小节连线、歌词和人工小节线都保留；前后 MIDI 音符及时间序列一致 |
| 移调等变 | 将有明确调性的合成音频整体移半音，推断 Do 同移半音；音级序列不变。不是只改文件元数据 |
| 半音证据 | 测试有 3–4、7–1 收束的旋律；也测没有 4/7 的五声旋律，不能把证据缺失判成错误 |
| 大小调 | C 大调/A 小调等关系调测试分别报告 tonic/mode/do；不得把二者混为一种“准确率” |
| 锚点 | 同一真实片段的多个不同音级推导一致；故意放入矛盾锚点必须显示冲突，不平均、不静默忽略 |
| Capo | E 指型+3=G、G 指型+3=B♭；参考谱已写实际调时不重复加 capo |
| 歧义/劣质 | 静音、单音、低覆盖、强打击乐、重叠人声、关系调歧义不得自动 confirmed |
| 持久化 | 锁定后改 BPM/重分析、保存/重开、导出/导入、恢复历史仍保持对应 KeyMap 和锚点 |
| 实曲 | 《千年之恋》至少开头 8 小节及主歌/副歌/尾段分别核对；真值须来自同一录音的人工听辨/测音与参考谱约定核对，不拿算法自己的结果当真值 |
| 回归 | 保留现有编辑、MIDI、歌词、小节和工程测试；本任务不顺便改用户的真实工程文件 |

真实自动准确率必须分开统计：`doPc exact`、tonic、mode、八度错误、半音音程错误。调性正确不等于旋律正确，八度错误不应混入 Do 音类错误。初期可用至少 30 首不同歌曲的人工标注开发/留出集合验证；同歌不同段/移调副本不得跨集合泄漏。高把握自动结果精度目标可设 ≥95%，但小样本只能报告实际 n/N 和不确定性，不能称为普遍保证。未达到就继续“建议+确认”。

## 8. 依赖与实施边界

首版采用项目已经安装的 librosa 0.11.0；不新增必须下载的选调模型，不调用云端。使用其谐波提取、CQT chroma 与调律估计作特征，候选评分和人工校准由项目实现。官方文档分别说明了这些接口：[谐波提取](https://librosa.org/doc/0.11.0/generated/librosa.effects.harmonic.html)、[chroma_cqt](https://librosa.org/doc/0.11.0/generated/librosa.feature.chroma_cqt.html)、[estimate_tuning](https://librosa.org/doc/0.11.0/generated/librosa.estimate_tuning.html)。这些接口不是自动准确识调的保证。

librosa 官方仓库为 [ISC 许可](https://github.com/librosa/librosa/blob/main/LICENSE.md)。依赖锁定及许可通知按项目已有流程保留。可以参考 [Essentia KeyExtractor](https://essentia.upf.edu/reference/std_KeyExtractor.html) 的 HPCP/调律/调性输出设计，但不要直接把它变成默认依赖或复制实现：其[官方许可说明](https://essentia.upf.edu/licensing_information.html)涉及 AGPL/商业授权，模型还有单独条款。本方案不依赖 Essentia。

本任务只解决 Do 的可信确定链路。碎音符、过多休止符和相对音程错误另立验收，不通过改调、全曲加倍 BPM、删除不合音阶的音来“美化通过”。调性只能为后续旋律解码提供软约束，原始观测必须保留，防止循环自证。
