# 多声部提取与试听

在主页 **1 听歌识别** 中导入歌曲，输入内容选“歌曲原曲”，然后选择“提取声部”：

| 模式 | 输出 |
| --- | --- |
| 四声部 `htdemucs` | 人声、鼓、贝斯、其他伴奏 |
| 六声部 `htdemucs_6s` | 上述四声部，另加吉他、钢琴 |

点击 **识别并提取声部**，处理当前选择的时间片段。完成后，人声播放器与“分声部试听”区域可分别试听；每个乐器播放器可下载 WAV。播放一个声部会暂停其他音频，切换工作阶段也会暂停。

六声部是 Demucs 官方实验模型，吉他和钢琴可能串音，尤其钢琴不稳定。某段没有该乐器时，声部可能接近静音。“其他伴奏”是一组剩余声音，可包含弦乐、合成器等，不代表识别了单独乐器。声部分离不能保证各轨完全干净。

**简谱仍只从人声声部提取。** 这版增加的是声部音频试听，没有增加吉他和弦、鼓谱或钢琴多声部记谱。“清唱／独奏”模式不进行乐器分离。

## 本机环境

已有音频环境时，只需首次运行：

```sh
npm run audio:stems
```

该命令下载六声部模型到本机 `.cache/torch/hub/checkpoints/`，生成 `.cache/audio-ready-6s.json`。当前官方权重文件为 `5c90dfd2-34c22ccb.th`。推理在本机 CPU 执行，没有云端推理 API。模型不存在时六声部选项显示准备命令，禁止偷偷退回四声部。

全新环境先运行 `npm run audio:setup`，再运行上述命令。准备后点“重新检查环境”。更新后端代码后，需要在你自己的终端重启 `npm run dev`。

## 关键实现

- [audio/separate.py](../audio/separate.py)：加载选择的模型，一次 `apply_model` 推理后遍历 `model.sources`，写出每个声部。各轨采用同一个防削波增益，保留声部间音量关系，不把很弱的残留声单独放大。
- [audio/transcribe.py](../audio/transcribe.py)：解码选定片段，调用分离进程；仍仅对 `vocals.wav` 使用 pYIN。结果新增 `separationModel` 与 `stems`，并保存 `stems.json` 模型与声部清单。
- [audio/api.mjs](../audio/api.mjs)：仅允许四/六声部模型，分别检查权重准备状态；WAV 接口支持已知六种声部和 Range 试听，不接受任意文件名。
- [src/stem-players.js](../src/stem-players.js)：两阶段共用的声部播放器，独立进度、互斥播放、下载及位置恢复。
- [audio/project-store.mjs](../audio/project-store.mjs)、[audio/project-archive.py](../audio/project-archive.py)：登记新 WAV、SHA-256 和 `stems.json`，一起保存到 `.jpp`。工程重开可直接试听，无需重新跑模型。

旧工程和旧任务只有人声，不凭空补出其他音轨；重新识别一次才会生成新声部。重新识别生成新 run，保留人工修订谱。

没有新增音频分离插件；继续使用已安装的 Demucs、PyTorch、soundfile 等，仅增加另一份模型权重。模型许可仍按[原有商业许可分析](歌声提取与旋律记谱-架构及商业许可.md)处理，不能因本机下载或新增声部而认定权重可商用。

## 验证

`npm test` 包含六声部工程包的逐文件往返校验。使用真实分离结果的浏览器验证：

```sh
STEMS_TEST_AUDIO=本地原曲.mp3 STEMS_TEST_OUTPUT=本地分离结果目录 node scripts/verify-stems.mjs
```

验证实际 WAV 播放、互斥播放、编辑器对照播放、工作阶段切换暂停、进度恢复、工程包逐字节恢复及手机布局。脚本通过独立浏览器路由访问真实 API，不启动监听服务。测试音频、权重、缓存和生成工程均由 Git 忽略。

模型说明来源：[Demucs 官方 README](https://github.com/facebookresearch/demucs/blob/main/README.md)。
