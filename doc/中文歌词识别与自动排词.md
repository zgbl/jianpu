# 中文歌词识别与自动排词（实验版）

## 一分钟使用

1. 在 **听歌识别** 完成主旋律识别，先试听提取的人声。
2. 点击 **识别人声歌词并填入简谱**。识别中文文字和词级时间，按时间填到本页草稿音符下方。低置信文字不自动填入，界面列出需要核对的内容。
3. 在谱面右侧 **正确歌词** 粘贴整首正确歌词，每句一行，点 **按正确歌词校准并排谱**。程序用连续匹配的词句作时间锚点，在锚点间补齐错字、漏字；当前片段之外没有时间依据的段落保留为待定位。点击锚点按钮可试听对应歌声。
4. 有带时间的歌词时，选择 **LRC 时间匹配**。可粘贴整首 LRC，例如 `[01:30.00]这一句歌词`；时间按原曲开头计算，程序只选取当前处理片段。
5. 没有可用时间信息时，选择 **按音符顺序初排** 和起点。该方式仅初排，不能判断实际歌唱位置，必须进入编辑器调整。

“搜索歌词”打开外部搜索页，用户自己选择并粘贴，不自动抓取网站或保证检索结果。搜索只发送输入的歌曲名与“歌词”，不上传音频。

第一次将结果送入编辑器时，生成谱包含本页歌词。如果已经有人工修订谱，用 **将本页歌词应用到已有修订谱**，只更新所选歌词段，保留音符。已有同段歌词会提示替换；无法定位的字不会在修订谱中被默默丢弃。

## 能力边界

中文歌唱中的咬字、拖长音、合唱、混响和错分离会导致文字或时间错误。Whisper small 是通用语音识别模型，并非专门的歌词模型，本版本不承诺识别正确率。

- 词级时间来自 Whisper；一个词含多个中文字时，字时间在词范围内均分估计。
- LRC 通常只有句级时间，句内逐字时间同样是估计。
- 锚点校准通过局部序列匹配，在完整歌词中定位实际识别片段；连续匹配至少两个字的词句可组成锚点，累计至少四个匹配字。漏字优先分配到锚点之间有旋律的时间，避开伴奏间奏；逐字时间仍是估计。没有足够锚点时拒绝校准；没有依据的段落保留待定位。重复副歌利用上下文和时间顺序匹配，并提示核对。
- 保留旧的“利用识别时间匹配”作为片段内小幅改字方式；整首歌词应使用新的锚点模式。
- 自动排词按音符来源时间定位，跳过休止、合并同音多字，保留延音拖腔。远离任何音符的字会报告为未定位。
- 简谱中的原始时间与小节位置、量化节奏存在差异，排好的结果仍需试听核对、逐字拖动修正。
- 无时间初排只按音符顺序分配。字数多于音符时允许同音多个字，不代表计算出了正确节奏。

## 本机安装与数据位置

已有音频环境后，首次执行：

```sh
npm run audio:lyrics
```

安装 `openai-whisper==20250625`、繁简转换依赖 `opencc-python-reimplemented==0.1.7`，下载多语言 Whisper small。权重保存在项目根目录的 **`.cache/whisper/small.pt`**，约 461 MiB；准备状态为 `.cache/lyrics-ready.json`。推理在本机 CPU 上运行，使用已经分离的人声 WAV，没有云端推理 API，不需要 API Key。

任务暂存在 `.audio-lyrics/<任务ID>/`。完成后，原始文字、词时间、概率和警告登记到工程的 `runs/<识别版本ID>/lyrics.json`，随 `.jpp` 导出、导入。粘贴的文字、匹配方式和排词方案保存到工程工作状态；谱面歌词保存到 `.jpu`。

恢复已保存结果不需要模型。服务中断的歌词任务需要重新识别；取消不会覆盖已有结果。工作目录、模型、音频及工程不上传 GitHub。

## 验证

`npm test` 包含跨小节/休止/同音多字/拖腔、LRC 时间偏移、文字修正、不匹配拒绝、初排和工程包歌词结果保存测试。

真实人声浏览器验收：

```sh
STEMS_TEST_AUDIO=本地原曲.mp3 STEMS_TEST_OUTPUT=本地六声部结果目录 node scripts/verify-lyrics.mjs
```

测试会真实调用本机 Whisper，并验证进度、填词、三种粘贴方式、保留修订谱音符、工程包/浏览器恢复、手机布局；使用临时工程和独立浏览器路由，不启动开发服务。

Whisper 的词级时间实现来源：[官方转录代码](https://github.com/openai/whisper/blob/main/whisper/transcribe.py)。词级时间也是实验功能。本次增加语音识别依赖，不改变原人声分离模型的许可条件；商业发行需分别核对各依赖和权重许可。

## 正确歌词锚点校准

`src/lyric-alignment.js` 的 `alignLyricsByAnchors` 使用局部序列动态规划，不依赖云端或新模型。只有连续的精确文字匹配保留为锚点；不把错字替换结果当作可靠时间。锚点之间在旋律发声区间内插值，可一音多字。粘贴全文、模式与排词方案仍随 `.jpp` 保存。

`tests/lyric-anchors.test.js` 覆盖约一半错漏、完整歌词中的片段、重复副歌、无关文本和连续时间段中的漏字。`scripts/verify-lyric-anchors.mjs` 用带时间的错漏文字验证侧边粘贴、锚点试听、保留未定位段落、仅更新编辑器歌词，以及工程包保存恢复；测试不启动开发服务器。
