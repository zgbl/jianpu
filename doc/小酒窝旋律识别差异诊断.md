## 确认的事实

参考截图“我还在寻”所在句的前五个音为 3、3、4、3、2，半音间隔为 0、+1、−1、−2（忽略节奏）。原始 result.json 的最早五个事件 MIDI 为 51、53、54、53、51，间隔为 +2、+1、−1、−2。若这些事件确实对应同一唱句，第一个音或事件对应关系错误；统一移调、改变 Do 或 Capo 都无法修复该差异。需要逐句试听确认事件与歌词对应，不能只根据当前歌词布局当作真值。

工程 Do 状态 unknown，C 是未确认预览。升号多与此有关，但它不能解释音程差异。没有据此认定录音实际调。

原始 10–20 秒窗口中，起点在窗口内的 19 个事件时长合计约 3.616 秒（含末事件跨出窗口）；多个事件仅 80–160 ms。这不是该窗口歌唱占空比的测量，但说明当前落谱输入已经高度碎片化。

当前 pipeline：htdemucs 人声分离 → librosa pYIN → voiced/RMS 掩码 → confidence >= .65 → MIDI 四舍五入 → 五帧中值滤波 → 再将不可靠帧清零 → 保留至少75ms的片段 → onset 再切分 → 同音间隙至多55ms合并 → 前端十六分网格及短间隙延续。

因此不可靠片段会直接变为空洞，随后填成休止；颤音、滑音、八度误判可能形成新片段；onset 未验证是否属于重新咬字，可能再切一次。原始事件已经短碎，不应仅靠排版隐藏问题。

截图有3.5/4、4.25/4、2.75/4等人工编辑后的容量提示。小节线/时值与四拍容纳量不一致是另一问题，不会改变旋律相邻半音。

1. 原曲与已分离人声取同一个10秒片段；用原始时间试听每个事件，记录人声是否清楚、是否合唱或残留器乐。
2. 同屏展示原始连续f0、voiced概率、被阈值丢弃帧、最终事件。先人工标定同句5–10个绝对音高和起止时间，保留未确认项。
3. 修正f0轨迹：音域约束、八度连续性、短暂低置信空洞修复；低置信不直接等同真实休止。不能把f0强吸到某调来掩盖错误。
4. 音符切分结合稳定音高段和人声重新起音证据；区分颤音/滑音与实际换音、同音重新发字。在量化前验证相邻音程。
5. 保存原始观测及修订事件；局部重新检测不要重复分离、不要覆盖人工编辑。比较原人声与未量化旋律试听，确认后才量化节奏和排小节。

## 本次代码试验（vocal-events-v2）

- pYIN分析窗从1024改为2048样本，改善低音周期观测；hop仍为256。
- .65作为可靠观测门槛，.35只用于有可靠观测支撑的连续音高段延伸。孤立低置信段不采用。
- 短暂偏音仅在前后同音时平滑；真实短步进和持续八度跳进保留。
- 同音之间不超过96ms、且人声能量未跌落的空洞才补齐；真实静音保留。
- 同音重唱切分要求能量下降与onset共同支持，避免仅靠频谱onset切碎延音。
- 保存pitch-observations.json逐帧观测和清理结果；result.json及谱内transcription保存算法诊断版本。工程归档纳入该资产。
