# 中文歌曲：用正确歌词重新听音对齐

## 目标与本次范围

用户贴入正确歌词后，系统重新定位每个字在歌声中的时间，再映射到谱面。人工拖动只是补救，不是主要流程。本次只给出方案，未修改算法，未启动服务，未改写用户工程。

## 已复现的问题

只读检查当前《有多少爱可以重来》录音工程，并调用现有纯函数复现：用户确实已经应用正确歌词，当前模式为 `timed`。

- 原 ASR 漏识别“常常责怪自己”，却在前奏产生“词、演、演、唱”。
- `correctTimedText()` 把正确歌词中的“责、怪、自、己”当作替换字，继承上述错误识别的时间。整句被安排在 1.7–12.46 秒，而“当初不应该”的旧识别时间为 29.12–33.22 秒。
- `applyTimedLyrics()` 再按字的时间中点寻找有音高的音符；距离超过 1.2 秒就不放入谱面。复现输出明确包含整句未放入：“常常责怪自己”。
- “把”的旧时间为 37.86–39.30 秒，现有算法拿中点 38.58 秒匹配，复现得到同一音符上的“有把”。旧时间是否准确，尚未进行真实音频逐字标注；不能直接把中点或起点视为真值。

相关代码：`src/lyric-alignment.js` 的 `correctTimedText`、`timedCharacters`、`applyTimedLyrics`、`alignLyricsByAnchors`；`src/lyric-workflow.js` 的任务完成与计划恢复流程；`audio/lyrics-asr.py` 的 Whisper 识别。

当前机制的问题：文字替换并不重新听音；词内字符均匀分时；匹配时丢掉了句子结构；替换字沿用不可靠时间；逐字贪心映射没有全局顺序约束；找不到音符时字从谱面消失。现有“锚点”模式更谨慎，但缺少首句锚点时也不能从音频找回首句，仅切换模式不能根治。

参考谱用于核对文字、音符和乐句，不直接作为此次录音的时间真值。参考图中“把”仍在“常常后悔没有”所在小节的后半段，随后“你留”接下去。因此粘贴歌词的换行不应强制换小节；实际录音版本、当前小节线和字的真实唱入时间必须分别核对。

## 推荐架构

正确歌词 → 乐句粗定位 → 歌声音频强制对齐 → 独立逐字时间线 → 有顺序约束的谱面映射。

ASR 保留：无正确歌词时提供文字草稿，有正确歌词时只提供粗定位线索。正确歌词成为权威文字来源，重新识别不得覆盖它。

### 1. 保留全文和乐句，先定位哪句在哪段音频

每句、每字分配稳定 ID，保留换行、重复段落和全文顺序。统一简繁和标点仅用于比较，不破坏显示文本。利用连续文字匹配、拼音近似匹配及声学评分生成多个候选；重复副歌必须结合前后句顺序选择，不能只取一次局部最优匹配。

复用已有 `vocals.wav`，不再次分离原曲。结合人声能量、谐波和可用的原始音高观测，建立宽松歌唱区间；不要把当前碎片化音符和休止符当作歌声存在的唯一依据。普通语音 VAD 容易漏掉长音，需要保留延音及区间重叠。

例如首句缺失，应从可靠的“当初不应该”前方搜索歌唱区间，评估“常常责怪自己”这一完整短句。不能继续把它塞进前奏误识别字的时间。若录音确实从中途开始，应标记“录音范围外”；声学证据不足则标记“待定位”，不得伪造确定时间。

### 2. 用正确文字进行声学强制对齐

强制对齐解决的是“这段已知文字在音频哪里唱出”，与重新猜歌词不同。先试本地中文 CTC 声学模型，对原有人声输出逐帧字符概率，再通过 CTC 动态规划求文字与音频的路径。

候选模型：`jonatasgrosman/wav2vec2-large-xlsr-53-chinese-zh-cn`。其模型卡标注 Apache-2.0、16 kHz 输入，WhisperX 的中文对齐配置也使用此模型。它训练于中文语音，不能据此保证对歌唱准确，必须先做本曲小样本实验。无需引入整个 WhisperX 或额外说话人分离依赖。

实现要求：

- 先粗定位，再用约 15–30 秒且有重叠的窗口细对齐；不要把完整长歌词一次硬压入整段录音。
- CTC 路径正确处理 blank、重复字符（如“常常”“明明”）、长音和停顿；不能均匀分配每字时长。
- 未登录字不得删除。必要时增加拼音/音素对齐适配器，而不是把不同字的时间当作相同。
- 分块结果去重，保证字符 ID 和时间单调，保留备选路径与置信度。无证据时拒绝定位。
- 所有时间使用统一原曲秒数，显式记录截取起点；模型内部相对秒数必须转换一次且仅一次。
- 原曲和分离人声可在低置信区间比较，但不得悄悄更换时间基准。

不要为了采用教程而升级整个音频环境。TorchAudio 的 forced_align 已进入弃用流程，可实现独立 CTC 动态规划或固定适配器版本。模型及依赖商业许可单独审核，不能默认所有对齐模型都允许商用。

### 3. 先保存逐字时间，再映射乐谱

每个字保存起点、终点、声学可信度和来源。字的起点才是主要排版定位线索，不能继续只取词区间中点。字音起点仍需要声学验证，不能把 Whisper 给出的粗起点直接当作准确唱入时间。

映射采用全局单调路径，综合字起点与音符起点距离、歌唱区间重叠、乐句顺序和音符持续时间。允许一音多字、一字多音、跨小节延音，不设“一字一拍”限制。不用歌词换行决定小节线。

当前音符识别仍有碎音和大量休止符：无法绑定可靠音符的字，仍按音频时间映射到小节内位置显示，标记“音符关联待确认”，不能从乐谱删除。显示层需要支持独立时间位置和小节内比例位置，重排小节后重新计算关联，但保留逐字音频时间。

歌词校准不得改 Do、绝对音高、音符 ID、节奏或用户编辑的小节线。歌词引导音符修正是后续独立功能，需要另行预览和确认。

### 4. 工程保存和交互

主按钮改为“按正确歌词重新听音对齐”。后台复用人声，显示“定位乐句 / 逐字对齐 / 排入乐谱”的阶段与实际进度。保留“识别人声歌词”入口。

已有正确全文不能被 ASR 任务完成时改回自动计划。结果先预览，低置信整句高亮，点击可循环试听；用户只需对少量不确定乐句提供时间锚点后重试该句，无须逐字拖动整曲。

新资产 `lyrics-alignment.json`，与原始 `lyrics.json` 分开保存。建议结构：

```json
{
  "version": 1,
  "audioHash": "…",
  "transcriptHash": "…",
  "timeBase": "original-audio-seconds",
  "clipStart": 0,
  "model": {"id": "…", "revision": "…"},
  "algorithmVersion": "…",
  "lines": [{"id": "line-1", "text": "常常责怪自己", "status": "pending"}],
  "characters": [{"id": "char-1", "lineId": "line-1", "text": "常", "start": null, "end": null, "status": "pending", "confidence": null}],
  "mapping": {"scoreRevision": "…", "items": []}
}
```

状态至少区分：声学定位、估计、待定位、录音范围外、人工锁定。映射保存 noteId 或独立时间位置。原始 ASR 不覆盖；重分析尊重人工锁定；缓存以音频、全文、模型和算法版本共同失效。更新归档白名单，测试关闭重开、导出导入和小节重排后恢复。模型缓存不打包进工程。

## 实施次序与验收

P0：建立上述真实失败样本；修复全文丢失和正确歌词被覆盖；保留待定位行。不要宣称这一步已完成声学对齐。

P1：独立中文 CTC 对齐脚本与后端任务接口，输入已有音频路径、正确歌词和粗锚点，输出时间资产。先实验开头四句，确认有效再扩到全曲；若语音模型歌唱效果不足，记录失败，不上线伪精确结果。

P2：全局谱面映射、独立时间位置渲染、分句重试、重复副歌处理、工程持久化和性能优化。

真实验证：对本录音开头约 30–60 秒选取 10–20 个实际唱入字，人工听音并标注参考时间，尤其首句、重复字、“把”、延音及停顿。参考图不能替代音频标注。对比旧 timed、旧 anchors、新声学对齐，报告整句漏失、字起点误差中位数及 P90、重复段误配、跨乐句错位、可定位覆盖率和正确拒绝率。100–150 ms 可作为清晰唱入字的目标误差范围，不是当前已达到的指标。

必须确保全部正确文字可追踪为已定位、待定位或范围外，不能通过隐藏难字提高准确率。再测同字连唱、一拍多字、一字多音、弱起、部分录音、重新划分小节、重新识别和关闭重开。单元测试通过不能替代真实歌唱对齐验证。

## 执行提示词

请按 P0→P1→P2 实现。本次核心是正确歌词驱动的声学强制对齐，不是扩大旧时间插值或改几个距离阈值。先保留当前工作区与用户工程，复用已有人声文件；不得再次分离、硬编码歌名或答案。未知时间保留待定位，字符不能静默消失。正确全文、原始识别、声学时间和谱面映射分开保存。当前乐谱有碎音，必须允许时间已定位但音符未关联的字显示。先报告真实短片段实验与限制，再扩展全曲。不要启动、重启或停止用户的 5173 服务，不自动提交或推送用户数据。
