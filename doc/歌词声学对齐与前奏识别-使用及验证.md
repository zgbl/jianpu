# 歌词声学对齐与前奏识别

## 如何测试

本版修改了服务器任务接口。请在你自己的终端停止原开发进程，再运行 `npm run dev`，刷新工作台；本次开发没有操作你的 5173 服务。

### 正确歌词

1. 打开已有歌曲工程。无需再次分离音轨。
2. 可以先“识别人声歌词”，取得粗时间线；这一步仍保留，但声学对齐允许没有旧歌词识别结果。
3. 右侧粘贴完整正确歌词，每句一行。
4. 匹配方式选“按正确歌词重新听音对齐（本地模型）”，点“按正确歌词校准并排谱”。旧工程恢复时可能仍显示旧匹配方式，需要主动切换。
5. 等待逐句进度，试听核对。黄色待定位歌词保留在谱面底部；有声学时间但缺少对应音符的字尽可能显示在时间对应位置，同时保留待关联提示。
6. 保存工程包。对齐时间资产与原始识别分开保存，重新打开无需重新计算。

本机已经准备模型。如果换电脑，先运行 `npm run audio:lyrics-align`；ASR 模型另用 `npm run audio:lyrics`。推理仅使用本地缓存，不调用云端 API。模型首次准备需要联网下载。

### 前奏

1. 右侧“前奏器乐旋律”选声部：普通四声部分离选“其他器乐”；六声部分离可选吉他或钢琴。缺少相应轨道时不会伪造结果。
2. 设置片段内开始、结束秒数，结束应早于首句人声。这里是识别片段内时间，不是截取前原曲的秒数。
3. 点“识别前奏并预览”，检查候选谱，点“试听前奏 MIDI”。空格沿用主播放器暂停/继续，另有“停止试听”。
4. 核对后点“将前奏加入当前谱”。前奏与演唱采用当前 Do、速度和节拍时间轴；开头的静音也保留。前奏与已识别人声重叠时拒绝应用。
5. 用当前谱的 MIDI 与原曲比较，保存工程。加入前奏会触发并谱重排；已有编辑通过现有修订保留逻辑迁移，当前已编辑谱进入工程修订历史供恢复。

前奏初版是连续频谱主旋律候选，不是全乐器自动编曲。和弦、多乐器交替、贝斯与旋律重叠可能误选，应先预览再加入。

## 实现

- `audio/lyrics-align.py`：本地中文 wav2vec2 CTC 模型，利用旧识别连续字锚点确定窗口，再用用户正确文本求声学路径；支持重复字的 blank 状态和拼音同音候选。弱证据保留 pending，不继承错字时间当作真值。
- 模型：`jonatasgrosman/wav2vec2-large-xlsr-53-chinese-zh-cn`；下载在 `.cache/lyrics-align`，通过 `ready.json` 检查准备状态。模型卡标注 Apache-2.0。新增依赖 transformers、pypinyin；不重新运行 Demucs。
- `audio/intro-melody.py`：读取已有器乐轨，提取频谱音高候选，动态规划平衡强度与音程连续性，再稳定音高、合并事件。输出带 intro 来源的 MIDI 事件与真实时间。
- `audio/lyrics-api.mjs`：统一异步任务，kind 为 asr / align / intro，支持查询进度、取消与持久化结果。
- `src/lyric-alignment.js`：按声学唱入时间关联音符；支持同音多字，独立保存全部字符及待定位项；不修改旋律。
- `src/lyric-workflow.js`：新增声学对齐模式；重新 ASR 不覆盖正确歌词计划。
- `src/intro-workflow.js`：前奏预览、MIDI 试听与显式加入；候选及已应用事件恢复到工程工作区。
- 归档增加 `lyrics-alignment.json`、`intro-melody.json` 白名单，保留原 `lyrics.json`。声学时间使用 clip-seconds，保持与现有音符 sourceTime 相同基准，并在结果中明确标记；音频 hash、文字 hash、模型 revision 和算法版本随资产保存。

## 真实验证与限制

只读使用当前《有多少爱可以重来》工程的已有人声、器乐和 ASR 结果，输出诊断到系统临时目录，没有改写用户工程。

开头四句声学实验：

- “常常责怪自己”：仍为待定位，现有中文语音模型对歌唱开头的证据不足。不能宣称首句漏失已经自动恢复。
- “当初不应该”：当、初、不、该获得候选时间，应仍待定位。
- “常常后悔没有”：不足整句可信覆盖，本版保留待定位。
- “把你留下来”：五字获得候选，唱入起点约 39.05、39.45、39.79、40.15、41.03 秒。这些是算法候选，没有人工标注真值，不能作为准确率结论。

同音字概率做折扣后用于求路径；声学分数不是校准过的正确率。当前算法是逐句有序窗口的实验实现，尚未实现全曲多候选乐句联合优化和完整歌唱专用声学模型。首句问题仍需进一步实验，不能通过调低阈值强行宣称解决。

器乐实验：原有 other 声部前 20 秒生成 51 个候选音；未人工确认曲目旋律是否正确。另用合成单旋律音阶检查音高与范围约束。

代码验证：CTC 重复字与不足帧数测试、歌词起点映射与多字同音、未定位保留、前奏重复应用及人声重叠保护、工程包资产保存重开测试。83 项不监听服务端口的 Node 测试通过；完整测试中的两个端口测试因沙箱禁止 listen（EPERM）失败，不能报告全套测试通过。没有启动新开发服务，尚未进行浏览器端点击交互验证。
