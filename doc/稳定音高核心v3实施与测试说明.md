# 稳定音高核心 v3：实施与测试说明

本轮实现 Astra 方案中的第一轮算法实验，不代表完整 P0/P1 已完成，也不代表真实歌曲音高已识别准确。保留旧 v2；未改 Do、节拍、小节、歌词匹配或前奏算法，未安装新模型。

## 已实现

- `audio/stable-pitch.py`：连续浮点 MIDI 输入；48/80/208ms 多尺度上下文检测核心，区分稳定中心与单向滑动；在核心上估计目标后才取整。长尺度振荡支持用于颤音，短尺度支持真实短音。
- 候选核心用动态规划分组，代价包含新事件惩罚及核心中心残差；独立半音核心和八度大跳保持分开。这是第一轮核心候选解码，尚不是方案中的完整起音/稳定/滑出/静默 HSMM。
- 保存表现起止、核心起止、浮点中心、核心离散度、滑入/滑出、待核对状态及参数。无稳定核心的连续滑动只生成不确定候选，不把经过的每个半音都变成音符。
- 缺测只有兼容音高端点与持续能量支持时才连接；不伪造缺测帧的基频。真实低能量间隙保留。同音重起音仍需 onset 与能量下降的组合证据，连唱但无能量凹口的同音尚可能合并。
- `audio/transcribe.py`：pYIN 保留未取整及未通过 voiced 掩码的观测；有声概率单列。记录采样率、窗长、hop、时间原点、库版本及人声音频 SHA-256。分离声源门槛仍保留，未把原曲伴奏当成主唱。
- `pitch-observations.json` 保存原始观测与能量；`melody-candidates-v3.json` 保存所选算法、核心诊断及同输入的 v2 对照事件。工程资产白名单、导入导出已更新；旧资产不迁移或覆盖。
- 页面增加“旋律分段算法”：稳定音高核心 v3（实验）/旧分段 v2（对照），选择会随工程工作状态保存。切换选项本身不更改当前谱。
- 谱旁增加“未量化旋律 MIDI”：按识别原始秒数、绝对 MIDI 播放，从当前音频指针开始；指针跟随，空格暂停/继续。它不经过 Do 变换、小节量化或人工改音。原有“当前小节 MIDI 试听”继续播放编辑后的谱，两者用途不同。

## 正确测试顺序

1. 先保存正在编辑的工程。后端新增参数需要由用户在自己的终端重启 `npm run dev`，然后刷新主页。代码会检查后端是否支持算法参数；旧服务不会静默忽略选择。开发者本轮没有操作 5173。
2. 建议用“另存为”建立测试工程，避免把实验草稿和手工校正混在一起。
3. 选择“稳定音高核心 v3（实验）”。识别长度默认仍是“全曲”；若先试一句，可以临时选15秒并填写开始秒数。
4. 点击“识别并提取声部”，完成后先播放提取人声，确认是主唱歌声。
5. 点击该句在谱中的音符定位，再点击“未量化旋律 MIDI”，和人声比较。先判断高低、相邻音程、是否有多余音；不要先改 Do 试图掩盖音程问题。
6. 再用“当前小节 MIDI 试听”判断排谱/量化是否改变了节奏。未量化试听不会反映你的手工改音，这是刻意保留的检测层对照。
7. 需要 v2 比较时另存一个测试工程，选择旧分段 v2，再识别相同区间。当前页面尚无“只重解码旋律、局部候选确认采用”面板；不要把这一功能误认为已完成。

已有歌曲可先用下面的缓存命令局部对照，绕过声部分离和 pYIN 重跑。将 `RUN` 换成既有运行目录，输出目录使用项目之外的新临时目录：

```sh
.venv-audio/bin/python audio/compare-pitch.py \
  --cache "$RUN/pitch-observations.json" \
  --vocals "$RUN/vocals.wav" \
  --start 10 --end 20 --output /tmp/jianpu-pitch-comparison
```

输出 `comparison.json`（旧/新事件、核心、参数、待人工确认清单）、`v2.wav`、`v3.wav`、`vocals.wav`。WAV 是按未量化目标音合成的对照声音。旧缓存没有完整元数据且 voiced 可能已被掩码，脚本会明确报告，不把缓存回放当作新的基频测量验证。

## 实际验证与限制

### 合成轨迹

9项 v3 测试覆盖：滑入目标音、真实连续半音及八度跳进、80ms短音、跨整数边界颤音、无稳定核心滑音、能量支持缺测与真静默、同音重起音、半音边界不确定性、有声概率弱尾音。7项原 v2 测试仍保留。本轮16项均通过。

### 完整音频流程

既有 `known-melody.mp3` 清唱/独奏模式经解码、pYIN、v3、节拍流程，输出8音：MIDI 60、62、64、65、67、69、71、72，与已知音列一致。旧 v2 显式选择也完成同一八音流程，输出音列一致。此输入不含真人滑音、伴奏泄漏及复杂辅音，不能据此推算歌曲准确率。音频输出仅写入 `/tmp`。

### 真实《小酒窝》只读缓存对照

源运行：`a32e6ce2-a051-48c2-90c8-55287b94e5b5`，区间10–20秒。使用既有 pYIN 缓存，能量与 onset 从同一已保存人声计算；未重新分离，未写入原工程。

- v2：21个事件；v3：22个事件，3个不确定事件。
- 总事件数没有改善，不能宣称垃圾音已经消除。
- 旧方法首事件 MIDI 50，新方法首候选 MIDI 51；但未完成逐音人工音高、边界和歌词对应确认，这不是“已纠正”的证据。
- 仍有多处短平台和疑似过渡产生候选音。原始稳定基频是否错半音/全音尚待独立核验。
- 对照文件在 `/tmp/jianpu-stable-v3-comparison`，含未确认真值模板；准确率明确为 null。没有按歌名或参考谱硬编码目标。

### 工程与界面

全套 JS 测试107项通过；Python 新旧分段测试16项通过。语法检查与 `git diff --check` 通过。JS 验证覆盖：未量化时间/音高不随 Do、BPM 改变；跨小节延音片段的指针时间；新诊断资产随 JPP 导出导入恢复。使用用户现有5173服务和独立临时合成工程验证了按钮启动、谱面指针出现、空格暂停后指针时间保持不变、停止按钮；未触碰用户歌曲工程。临时工程和测试浏览器标签已清理。

## 下一步判据

先对同一句人声和未量化 MIDI 试听。如果稳定长音仍错半音或全音，进入独立基频检测器及谐波证据交叉验证，不继续靠核心分段调参来宣布正确。如果长音基本正确而短平台/滑音假音突出，再扩展序列模型及短音/重起音证据。若未量化旋律可用、简谱仍乱，则分别检查节奏量化与歌词关联。

尚未实现：第二检测器、整体调律估计、原始 f0 合成试听、完整状态序列模型、局部旋律重识别 UI 与确认采用、人工确认的真实歌曲准确率评估。保留这些边界是为了让这一轮能独立验证算法改动。
