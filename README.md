**谱间 · 简谱编辑器**

旋律和歌词的本地编辑工作台，使用 JavaScript ES Modules + SVG，无前端依赖。

[歌声提取：实现、架构及商业许可](doc/歌声提取与旋律记谱-架构及商业许可.md)。Demucs 代码为 MIT，但当前官方预训练权重未核实商业授权，作者说明其仅供科研；本机附带 FFmpeg 为 GPL 构建。不能把现版视为已经完成商用许可审查。

仓库仅提交源码、测试代码和文档。`SampleSheet/`、MP3、生成的 `.jpu` / `.jianpu`、预览图、模型缓存及虚拟环境保留在本机。新克隆可新建乐谱；歌曲示例和依赖本机音频/谱例的测试，需要自行准备相应文件。

**识别在哪里运行？模型在哪里？**

识别在运行本项目的电脑上完成，当前使用 CPU，**没有调用云端音乐识别 API，也没有把歌曲上传到第三方**。浏览器调用的 `/api/audio/…` 是本机 Node 服务；它启动本机 Python，先用 Demucs `htdemucs` 提取人声，再用 librosa pYIN 跟踪音高。pYIN 是算法，不需要另一份神经网络权重。

所有路径均相对于项目根目录：

| 路径 | 内容 |
| --- | --- |
| `.cache/torch/hub/checkpoints/955717e8-8726e21a.th` | 当前 HTDemucs 模型权重，约 80 MB |
| `.cache/audio-ready.json` | 模型准备状态及权重路径记录 |
| `.venv-audio/` | 本机 Python 环境，包含 Demucs、PyTorch、librosa 等依赖 |
| `.audio-jobs/<任务ID>/` | 上传的音频、解码片段、提取的人声和识别结果 |

新机器先安装 Python 3.12，再在项目根目录执行 `npm run audio:setup`，安装依赖并下载模型；第一次准备需要联网。依赖和权重缓存齐全后，推理可以离线执行。模型加载时若缓存缺失，Demucs 可能尝试重新下载权重；下载模型不等于调用云端推理。上述环境、权重和歌曲文件均不提交到 GitHub。

关键代码：[模型加载与 CPU 推理](audio/separate.py)、[音高提取](audio/transcribe.py)、[本机任务接口](audio/api.mjs)。完整架构及许可分析见前面的说明文档；本地运行不会解除预训练权重的商业使用限制。

**启动**

```sh
git clone https://github.com/zgbl/jianpu.git
cd jianpu
npm run dev
```

需要 Node.js 22 或以上。首次运行或依赖更新后，在项目根目录执行 `npm install`，然后运行 `npm run dev`。打开终端显示的地址，默认 `http://127.0.0.1:5173/`；占用时尝试后续端口。服务由你在终端控制，Ctrl+C 停止。

视觉识谱页默认提供“粘贴 JPU 生成乐谱”，无需登录或图片。切换“上传图片 · 在线识别”后默认选择 Gemini。也可以选择 OpenRouter：在项目 `.env` 填 `OPENROUTER_API_KEY`，在“模型 ID”输入框从图像模型目录中搜索选择（或填完整 ID，如 `openai/gpt-4o`），也可设置 `OPENROUTER_MODEL` 作为默认值。OpenRouter 请求使用你账号的余额，页面会显示模型返回的文本增量和处理中状态。其他 API 服务通过各自的 Key 配置。ChatGPT Plus / Pro 登录授权方式见[ChatGPT 计划额度接入说明](doc/ChatGPT计划额度视觉识谱使用说明.md)。

根地址是统一歌曲工程工作台。**识别结果在同一页原地编辑**，上方试听音轨，下方直接改音符、输入歌词、插入／删除／拖动小节线；共用新建、打开、最近工程、修订版本、保存和另存为。原曲、人声、识别结果、修订简谱和工作位置自动保存在本机 `.projects/`；保存完整 `.jpp` 工程包后，可在另一台机器重新打开。旧的 `/?score=…` 链接可导入为工程。

[歌曲工程使用说明](doc/歌曲工程使用说明.md)。本机自动保存与外部工程包保存分开显示；携带或备份请保存 `.jpp`，单独 `.jpu` 只包含乐谱。

[一分钟用户手册](用户手册.md)；界面顶部“一分钟上手”可随时查看。

**多声部提取与试听**

听歌识别页可选四声部（人声、鼓、贝斯、其他）或六声部（另加吉他、钢琴）。首次使用六声部运行 `npm run audio:stems`；推理在本机进行，完成后分别试听、下载 WAV，并随 `.jpp` 保存。吉他与钢琴属于实验性分离；简谱仍只识别人声。[实现与使用说明](doc/多声部提取与试听.md)。

**中文歌词识别与排词（实验）**

识别页显示阶段进度条、百分比和已用时间。完成旋律识别后可从人声识别中文歌词及时间，自动填到简谱下方；错字和时间需要核对。首次准备运行 `npm run audio:lyrics`，本机 Whisper small 权重位于 `.cache/whisper/small.pt`。支持粘贴文字沿用识别时间、LRC 时间匹配及无时间的音符顺序初排。原始歌词结果和排词方案随工程保存。[使用与实现说明](doc/中文歌词识别与自动排词.md)。

**简谱播放与 MIDI**

编辑器顶部可播放、暂停/继续、停止，选择从头或当前小节并调整 BPM；播放基于当前音符、调号和时值，修改后重新播放。听歌记谱页也按排好的简谱播放。统一工作台支持标准 `.mid` 下载；浏览器内使用 Web Audio 合成，不依赖插件或硬件。现版不展开反复与结尾括号。

**同一谱面的基本工作流**

- 新建 / 打开 / 保存：使用顶部工程栏。`.jpp` 包含全部音频和当前谱，`.jpu` 仅含乐谱；单独谱可通过“导入 .jpu”打开。
- 识别完成即进入可编辑谱面；不需要转入另一个页面。点“选择 / 改音”，再点音符，按 0–7 改音高。
- 写谱：选择“写谱”，设置时值与八度，按 `2363` 连续输入；鼠标数字按钮同样可用。`[` / `]` 缩短 / 延长时值，↑ / ↓ 改八度，`.` 附点，Shift + 数字临时减半。
- 插入空小节：点目标小节后，“＋ 空小节”或 Enter，在当前小节后插入并开始写谱。
- 小节线：点音符后“＋ 小节线”，在音符前分开；选线 Delete 合并；抓线或底部圆点拖动调整相邻小节分界，音符与歌词保留。
- 编辑工具支持撤销 / 重做；Shift 点击扩选，“更多”中复制、剪切、粘贴、全选、导出 SVG、打印 / PDF。
- 单声部支持 4/4、3/4、2/4。详情见[歌曲工程使用说明](doc/歌曲工程使用说明.md)。

**歌词**

点“歌词”，点谱面文字或音符下的虚线空格，直接输入，Enter 保存，Esc 放弃当前输入；中文输入法组合过程中不提交。一音可填多个字。

拖文字时目标已有歌词向后让位。工具栏可选择“本行后续跟随”或“只拖这个字”；同音多字也可拆开逐字移动。支持 1–4 段歌词。自动识别和全文粘贴校准仍在右侧，修改直接写入当前谱。

**验证**

```sh
npm test
```

只运行音乐与工作台模型检查（无需启动服务）：

```sh
node --test tests/model.test.js tests/song.test.js tests/workbench.test.js
```

`scripts/verify-unified-editor.mjs` 是统一工作台的实际浏览器检查（设置 `RHYTHM_TEST_PROJECT` 指向本地 `.jpp` 工程）：需要 Playwright 和 Chrome，默认使用本机 Codex 的运行时，也可设置 `PLAYWRIGHT_MODULE`。所有页面请求由本地文件模拟响应，不启动开发服务器或占用开发端口。

编辑器仍不支持多声部、三连音和图片识谱。识别 Demo 支持试听，自动转录的升降号可以保存、显示，并在音符属性里修改。

文件后缀：新建和另存为默认使用 `.jpu`（JianPu）；打开同时兼容旧 `.jianpu` 和 JSON。内部格式标识仍为 `jianpu-melody`，版本为 2。已有旧文件保留。


**听歌记谱 Demo**

打开主页 `http://127.0.0.1:5173/`，导入歌曲后直接识别和编辑。本机已准备音频模型；原来运行中的开发服务器需重启一次，加载新增接口。其他机器先执行 `npm run audio:setup`。

歌曲 MP3 先分离人声，再识别单条旋律，显示 SVG 简谱；支持原曲／人声／识别旋律试听、速度调号修改、下载 `.jpu` 和在当前谱面直接修订。建议先试 30 秒有人声片段。合唱、和声、说唱、残留伴奏及器乐主旋律仍可能导致错误，结果需人工核对。歌曲在本机处理。
